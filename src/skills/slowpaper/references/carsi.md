# CARSI 机构登录

CARSI（教育网联邦认证）让用户用**本校账号**访问机构订阅的文献库。这一期只做一件事：
**登录成功**。不下载、不做多机构、不写任何 SP 的检索指令。

**这是一份操作手册。** 侦察记录（清单接口的四个坑、判据为什么是 origin 精确相等、
还没验证的那几条）不在这里 —— 那些是实现者的材料，不是你的操作步骤。

---

## 一、整条路走一遍

1. **前提是用户已经在设置里配好机构账号。** 没配的话 `browser_login` 的说明里会写着
   「设置里**还没有配置机构账号**」—— 那就直接告诉用户去设置里配，别调这个工具试试看。
2. `browser_open` 打这个 SP 的登录入口 URL（怎么拼见 §二），落到本校的统一身份认证页。
3. **先看一眼快照**：这一页有没有验证码、账号框是哪一个。
4. 调 `browser_login`（参数与五条铁律见 §三）。
5. 看**工具结果头部**那行「机构登录: …」—— 它是唯一的成功判据（§三）。

登录成功之后，这个标签上的会话就带着订阅权限了。**但这一期仍然不下载任何文件** ——
拿到订阅访问权也只是把链接报给用户。

---

## 二、登录入口 URL 怎么拼

选中机构后，SP 的入口 URL 形态是：

```
https://fsso.cnki.net/Shibboleth.sso/Login
  ?entityID=<机构的 entityID>
  &target=<登录成功后要去的 SP 页面>
```

这是 Shibboleth SP 的标准形态，各 SP 的域名不同、路径通常一致。

**`entityID` 从哪来：`browser_login` 自己的工具说明里就写着**「当前配置的机构：…，
entityID：…」。那一行是建会话时的快照，用户中途换了学校就旧了 —— 每次调用的**返回值**
里都会回显当前的机构名与 entityID，**以返回值那一份为准**。

**跳转链**（知道它是为了看懂自己走到哪一步了）：SP `/Shibboleth.sso/Login` → IdP →
（可能再跳到本校真正的登录页）→ 用户登录 → IdP 把 SAML 断言 POST 回 SP 的 ACS 端点 →
SP 种会话 cookie → 落到 `target`。

## 三、`browser_login` 怎么调

参数只有四个：

| 参数 | 给不给 | 是什么 |
| --- | --- | --- |
| `tabId` | 必给 | 机构登录页所在的标签 |
| `submit` | 可省 | 填完是否立刻提交表单。**不给就是不提交** |
| `usernameIndex` | 可省 | 快照里账号框的编号 |
| `snapshotId` | 可省 | 给了 `usernameIndex` 就必须同时给产生它的那份快照号 |

账号与密码由主进程直接填，**你看不到也拿不到**（密码连主进程之外都不出）。

### 铁律 1：`submit` 不给就是只填不提交

**默认是不提交。** 不是「看见验证码才传 `submit: false`」—— 反过来，
**要提交才必须显式写 `submit: true`**。

这是刻意的：验证码是**常态路径**不是边角情况，而两个方向的代价不对称 ——
多提交一次会在有验证码的页面上送出一次必然失败的登录，用掉本轮**唯一**那次机会；
少提交一次只是让你多点一下提交按钮，随时补得回来。

不提交时返回值会写「**没有提交**（你没给 submit: true）」，页面上这时账号与密码已经填好了。

### 铁律 2：成功判据只有一句话

**工具结果头部那行**：`机构登录: [tab_…] 已看到 SAML 断言回传`。

只有这一句算数。**页面文案不算、跳转到了哪一页不算、HTTP 状态码也不算** ——
密码错时多数 IdP 回的是 200 错误页或者 302 回自己，页面看起来一切正常。

这一行挂在**每一个**浏览器工具的结果头部，不是只有 `browser_login` 才有：`submit` 不给
那条路上，断言回传发生在你自己点完提交之后，那一刻 `browser_login` 早就返回了。
还没看到回传时那一行写的是「已经填过一次凭据，还没看到断言回传（本轮不会再填第二次）」。

### 铁律 3：一轮只有一次机会，别写重试

**同一轮任务里填过一次而没看到断言回传，再调只会被拒**（`browser.login_attempted`），
**换一个标签页也一样** —— 那道闸的作用域是这一轮任务，不是这个标签。

理由：高校的统一身份认证普遍会**锁定连续失败的账号**，押的是用户自己的校园账号。
拿到 `browser.login_attempted` 就**交给用户**：让他自己在这个内置浏览器里登录，
或者去设置里核对机构账号与密码。**不要重试、不要换标签再试一次。**

### 铁律 4：账号框自己指最准

先取一份快照，把账号框的编号用 `usernameIndex` + `snapshotId` 指给工具。

不指也能跑 —— 结构规则找「同一个 `<form>` 里、排在密码框**之前**、可见、没禁用的
文本输入框」。但返回值会**回显实际选中的是哪个框**，形如
`实际填的账号框：input#user[name=userName]（按结构规则找到的）`。**看一眼它对不对**：
不对就别再调这个工具（那会用掉本轮唯一的机会），先告诉用户。

密码框由主进程自己找，只认「此刻就是密码框」或「这个文档里曾经是」；多于一个就整条拒绝。
`usernameIndex` 指到密码框上会被当场拒掉（`browser.password_field`）—— 两个框别指反了。

### 铁律 5：验证码页的标准剧本

验证码是常态，走这四步：

1. `browser_login({ tabId })` —— **不给 `submit`**，只填账号与密码
2. `browser_act` 把验证码填进验证码框（`type` 打**验证码框**是可以的，打**密码框**会被
   直接拒绝，报 `browser.password_field`）
3. `browser_act` 点页面上的提交按钮（**别指望 Enter**，见 `browser.md`）
4. 看下一次工具结果头部那行「机构登录: …」—— 铁律 2

**第 2 步之前要不要问用户？** 图片验证码你自己读不出来 —— 那就调 `ask_user_question`
带上 `browserTabId`，让用户自己在侧栏里填验证码并点提交，然后你只负责读那行状态。
短信码与 OTP 同理，一律交给人。

## 四、七类错误码，各自的下一步不一样

**不要把它们收敛成一句「登录失败」**，每一类的下一步都不同：

| 错误码 | 意思 | 你的下一步 |
| --- | --- | --- |
| `browser.idp_host_mismatch` | 这一页不是（或已经不是）确认过的机构登录页，**一个字都没填** | 先导航到这个机构自己的统一身份认证页，再调一次 |
| `browser.target_unusable` | 页面上的框不对：没有密码框 / 有多个 / 你指的那个不是文本框、被禁用、与密码框不在同一个 form | 换一页（多半还没走到输密码那一屏），或者用 `usernameIndex` 指一个 |
| `browser.stale_index` | `usernameIndex` 指的编号在当前文档里找不到了 | 重新取一份快照，用新快照里的编号再调 |
| `browser.page_no_result` | **这一步做到哪一步我们不知道** | **别按「它没做」去重试** —— 先取一份快照看页面现在什么样 |
| `browser.login_attempted` | 本轮已经填过一次，没看到断言回传 | **交给用户**，本轮别再试（铁律 3） |
| `settings.invalid` | 设置那一侧的问题：没配机构 / 没设密码 / entityID 是 URN 自动登不了 | **交给用户**去设置里补 —— 换一页再试一百次也一样 |
| `settings.secure_storage_unavailable` / `settings.stored_password_unreadable` | 前者是钥匙串这一刻不可用（**密码没丢**），后者是已存的密文永久解不开 | **两条别合并**：前者让用户修好钥匙串再试一次；后者修钥匙串没用，只能请用户重新填一次密码 |

`browser.password_field` 是第八种、也是最容易自找的一种：`usernameIndex` 指到了密码框上。
改指账号框即可，这一次一个字都没填。

## 五、这一页长什么样：变异很大（两个实测样本）

|  | 北京大学 | 中科院（127 机构共用） |
| --- | --- | --- |
| entityID host | `idp.pku.edu.cn` | `passport.escience.cn` |
| **实际登录页 host** | **`iaaa.pku.edu.cn`** —— **不一样！** | `passport.escience.cn` —— 一样 |
| 账号字段 | `userName`（`#user_name`） | `j_username` |
| 密码字段 | `password`（`#password`） | `j_password`（`#password`） |
| 验证码 | **有**：图片 `iaaa.pku.edu.cn/iaaa/servlet/DrawServlet`，另有短信 `sms_code` 与 OTP `otp_code` | **无** |
| 提交 | `#logon_button`（`type=submit`） | `_eventId_proceed`（`type=submit`） |

这张表**不是给你照抄的选择器清单**（字段名两个样本一个都不一样，写死必错），
它要说明的是三件与你的操作直接相关的事：

1. **登录页的 host 常常与 entityID 的 host 不一样**（北大就是），这是常态不是异常。
   所以第一次遇到一个新地址时工具会**停下来问用户一次**「这是不是这所学校的登录页」；
   用户确认过的地址会被记住，之后不再问。返回值里会写「用户刚刚确认了 … 已经记住」。
2. **字段名不能照抄**：主进程找的是页面上的 `input[type="password"]`，再取同一个 form 里
   它前面那个可见文本框当账号框。你要做的是**看一眼回显对不对**（铁律 4）。
3. **验证码是常态**：北大这一页同时有图片验证码、短信码与 OTP。所以铁律 1 与铁律 5。

## 六、这一期的边界

- **只做登录，不下载。** 登录成功之后拿到的订阅访问权，仍然只用来把链接报给用户。
- **只支持一个机构**：设置里配的那一个。用户中途换了学校，以返回值里回显的那份为准。
- **SP 会话通常是会话 cookie**，KyDog 重启之后不保留 —— 下一轮任务要重新登一次。
- **有些学校不允许从 `fsso.cnki.net` 直连**，要求从本校图书馆门户进。撞上了就交给用户，
  别自己去猜门户地址。
