# 网页研究

输出用用户提问的语言写成 **Markdown 研究报告**。研究输入限 HTML 与纯文本网页；不读取 PDF 正文。搜索引擎只由 KyDog 内置浏览器的 `browser_open`、`browser_act` 操作；`web_research_collect` 只抓取已经发现的目标 URL。

## 1. 定范围

保留用户的原始问题。拆出有明确 `id`、`label`、`query` 的研究角度；需要解释角度选择时写 `rationale`。标明要核对的版本、发布日期范围和判定条件。用户未指定预算时使用工具默认预算；用户指定来源或预算时据此执行，不默默扩大上限。

## 2. 用 IAB 跨引擎发现

先读本 skill `references/` 下拟用引擎的操作卡。当前已实测 DuckDuckGo 的搜索与改词，以及 Bing 的直接结果页入口和单次结果抽取；Google、百度在实测网络出口受到验证页阻断，其结果抽取尚未验证。默认对同一个 `query` 分别尝试 DuckDuckGo 和 Bing。用户指定其他引擎时，按相应卡片尝试并依据**当前 IAB 返回**记录结果或阻断，不声称未抽到的结果已经找到。

每次检索保存一个唯一 `attemptId`、`engineId`、原样 `query`、`angleIds`、搜索页 URL 和状态。`browser_act` 抽出的每个候选保存所属 attempt、角度、引擎、query、标题、摘要、目标 `@href`。同一目标被多个引擎命中时保留全部发现背景。页面明确显示没有结果才能记 `explicit_empty`；验证码／挑战记 `blocked`，导航失败和抽取失败分别记录。零条抽取不能自动解释成零结果。明显的 PDF 链接不纳入正文候选；目标 URL 实际返回 PDF 时采集器会标为不支持媒体。

搜索摘要已经提供线索：看到术语歧义、相反说法或缺少新版文档时，可以立即改词再搜。是否需要下一轮由实际观察和研究缺口决定，**不预设轮数**；摘要只能指导发现，不能成为最终证据。

## 3. 分批采集与续查

用 `web_research_collect` 传 `originalQuestion`、`angles`、`enabledEngines`、`attempts`、`discoveries`。不要传 thread ID，工具会绑定当前对话。可以先采一批 URL，再根据返回的角度汇集和 `gaps` 继续 IAB 搜索；续查时传返回的 `researchRunId` 和新的 attempts／discoveries，保持原问题不变。明确要求刷新已有网页时才设 `refresh: true`。

采集器负责 URL 去重、预算、跳转、并发抓取、独立抽取和引文核验。主对话只接收压缩后的主张、证据 ID、来源状态和缺口；不要把整页正文搬进对话。抓取失败、验证页、PDF 或模型未完成要保留为限制，不能改称“无关内容”。

## 4. 核对并写报告

对计划引用的证据 ID 调 `web_research_evidence`，每次最多 4 个；核对原文片段、最终 URL 和支持／反证关系。只有 `grounded` 的原文引文能支持具体结论。不同来源相矛盾时并列列出，不用搜索引擎命中数投票。报告至少交代研究问题、方法与检索范围、发现、逐条来源链接、冲突和未解决缺口；具体主张旁给出可打开的最终 URL 与证据 ID。无法打开或未读取正文的搜索结果只放在限制中。
