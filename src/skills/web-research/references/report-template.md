# 网页研究报告模板

这是一份结构约束，不是固定章节清单。按研究问题增删「主题发现」下的章节；保留其余部分，以便读者知道结论来自什么范围、哪些问题仍未解决。

每个解释架构、工作原理、数据流、控制流、状态变化、角色协作或跨组件交互的主题章节须包含至少一幅 Mermaid 图，使用标准 `mermaid` fenced code：

- 架构／数据流用 `flowchart`。
- 泳道用 `flowchart` + `subgraph`。
- 协议／调用交互用 `sequenceDiagram`。
- 状态生命周期用 `stateDiagram-v2`。

图紧邻解释；节点和连线须由证据支持，推断须在图旁正文中标明。引用留在相邻正文中，不写进 Mermaid；普通事实不加装饰图。

```markdown
# {{研究主题}}

> 原始问题：{{用户的原始问题}}
>
> 检索日期：{{YYYY-MM-DD}}

## 结论摘要

用短段落直接回答问题，区分已核实结论、条件性判断和仍不确定的部分。

## 主题发现

### {{由问题决定的主题}}

陈述具体发现，并在草稿中写 `[来源标题](最终URL)〔证据:evidenceId〕`。同一来源的多条证据可写成 `[来源标题](最终URL)〔证据:id1,id2〕`；不同来源分别给链接。`complete` 核验后会从成品删除内部 ID。

## 冲突与未核实项

- 写明来源之间的矛盾、版本或日期边界。
- 写明搜索摘要线索、抓取失败或证据不足而不能确认的事项。

## 方法与覆盖范围

- 实际使用的搜索引擎与 query 范围。
- 已入队、已处理、有证据、无相关主张、失败和未处理来源数；不要把抓取预算上限写成计划抓取总数。
- 关键筛选方式，以及未覆盖的语言、时间或站点范围。

## 限制与开放问题

记录尚无可执行检索路径的问题，以及预算、访问限制或资料质量对结论的影响。
```

成品只保留可点击的 `[来源标题](最终URL)`；不得出现 `evidenceId`、`sourceId`、`claimId` 或其他内部键。浏览器直接查阅但未进入证据库的页面，须以普通 URL 链接标注「本轮直接查阅、未纳入正文证据」。
