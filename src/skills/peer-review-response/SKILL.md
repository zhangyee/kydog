# 同行评审（评别人的稿子）

输入是**别人的一篇稿子**，输出是**一份正式评审报告**。这份报告会以用户（审稿人）的名义提交出去——每条意见都要经得起作者反查，一条查不实的意见就足以让整份评审失去分量。

评审规程本体在 `references/review-kernel.md`（评审内核），与 `/peer-review` 共用——两个 skill 各带一份逐字节相同的拷贝，单测钉死。改内核必须两边一起改，别只按「评别人」的场景来权衡。

## 和其他 skill 的分工

| | 问题 |
|---|---|
| `/peer-review` | 我自己的稿子该怎么改 |
| **`/peer-review-response`** | **别人的稿子行不行、意见怎么提** |
| `/fact-check` | 这一句话成不成立 |
| `/paper-summary` | 这篇论文怎么写进我的论文 |

评审中某条具体断言拿不准对错（「作者说 X 已被证明」到底证没证过），那是 `/fact-check` 的活，别在评审里顺手下结论。

## 开工前

1. `date +%F`
2. `ls papers/` —— 稿件和相关论文可能已经在里面。
3. **read fastpaper 的 SKILL.md**（在 `<available_skills>` 里）——文献覆盖与引文抽查要用。
4. 拿到稿件。三种形态：项目里的 Markdown、`papers/` 里的 PDF（`fastpaper read` 分节读）、用户粘贴的文本。
5. **全文是硬门槛。** 只有摘要做不了评审——方法细节、统计报告、作者自己承认的局限全在正文里。拿不到全文就停下来问用户，不要默默用摘要顶上。
6. 用户是受邀的正式评审时提醒一句：不少期刊限制在评审中使用 AI；KyDog 在本地运行、稿件不出这台机器，但要不要用、意见以谁的判断署名，是用户自己的决定。说一次就够。

## 怎么跑检索命令

AGENTS.md 的「用工具的方式」全部适用。只有一样东西该写进磁盘：最终那份评审报告（以及 `fastpaper download` 自己放进 `papers/` 的 PDF）。不建目录、不写脚本、不落中间文件。

检索用默认 table 格式（`-n 8`），看中再 `fastpaper get <id>`。下载失败先看退出码：`4` = 这个源就是没有，换个源才有意义；`2` = 命令写错了；`1` = 别的问题。

## 评审内核（第 1–3 步）

**read `references/review-kernel.md`，照它跑**：中性映射 → 整体判断 → 逐条检查，严重度判据、意见五要素、编号规则、文献列举要求全在里面，本文不重复——**凭记忆评审必然退化**。

**每进一个阶段用一两句话告诉用户你在做什么**（「先把稿子通读一遍」「现在检索核验它声称的贡献」「在逐条过方法与统计」）——读稿和检索会静默几十秒，不说话用户只能盯着转圈猜。

## 写报告

模板在 `assets/report-template.md`，用 `write` 写到**项目根目录**：

```
peer-review-response-<稿件简称>-YYYY-MM-DD.md
```

稿件简称用短横线连接的英文或拼音。**模板里 `〔写作指导〕` 开头的引用块整块不进报告**，一条都不许留；其余 `>` 引用块是报告的一部分，原样保留并填好占位符。**只用纯 Markdown，不写 HTML 标签**——KyDog 的渲染器没有 rehype-raw。

**报告用稿件的语言写**（英文稿出英文意见，模板节名一并译过去——作者要能直接读），和用户的对话照常用用户的语言。

写完在对话里给三句话：总体判断、最要紧的一两条 Major、报告路径。**提醒用户：提交前自己通读一遍，这份意见署的是他的名。**

## 诚实边界

- **只评纸面。** 缺章节照评，但报告开头声明「部分评审」并列出缺了什么，**不推断缺失内容**。
- **文献类断言一个都不许凭记忆。** 「已有人做过」「漏引」「引文不支持」都必须检索或回源确认；搜不到就写「在这些源、这些词下未找到」。
- **一个 id 都不许编。** 评审引用的每篇文献给完整出处且回源确认过——审稿人也要拿得出证据。
- **「本评审的局限」一节必须写**：检索覆盖到哪、哪些判断依赖领域常识而非检索、图表能不能看。让编辑和作者知道这份意见核到什么程度。
