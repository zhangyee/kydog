# 检索战术

配合 SKILL.md 第 1 步。前置：已读过 fastpaper 的 SKILL.md。

**这里是两条独立的线，不是一条流水线。**

- **A + B 建立共识地图**：这个方向公认的正典是什么。靠综述和它们的引用链交集。
- **C 找前沿**：最近在发生什么。**不依赖 A 和 B 的任何产物。**

把它们混成一条线是个常见错误，后果是前沿被综述定义。综述按定义是**沉淀下来**的东西——检索截止往往比出版年再早一年——它告诉你什么已成共识，不告诉你什么正在发生。

阶段之间只有一处真依赖：B 需要 A 的结果。所以 **A 和 C1 并行起跑**，B 之后再跑 C2。

先撒网搜主题词的做法不可取——会淹在几百条中等相关的结果里，且分不出哪些是真经典。但这只是"找正典"的约束，不是让前沿排队的理由。

### 引用链的盲区

B 和 `cite --direction incoming` 都建立在引用边上，所以它们**结构上只能找到与既有正典连着的工作**。以下几类断连的工作，引用链一篇都看不见：

| 断连的类型 | 为什么断 |
|---|---|
| 跨学科带方法进来的人 | 引的是**他们那个领域**的正典，不引这里的 |
| 换了术语的新子方向 | 关键词和引用双双对不上 |
| 预印本、工业界工作 | 很多根本不进引用网 |
| 刚发表的 | 还没来得及被引，也来不及引最新的 |

所以 C 必须有**不经过引用链的入口**。见下面 C1 的三条。

---

## A. 找综述

### 用出版类型过滤（最准）

`pubmed` 和 `pmc` 原样透传 query，它们的 `[pt]` 字段可用：

```bash
fastpaper search pubmed "<主题> AND review[pt]" -n 10
fastpaper search pubmed "<主题> AND systematic review[pt]" -n 10
fastpaper search pubmed "<主题> AND meta-analysis[pt]" -n 10
```

三种要分开搜，它们是不同的东西：`review` 是叙述性综述，`systematic review` 有预注册的检索协议，`meta-analysis` 有合并统计量。**在报告里要区分**——一篇 meta 分析的结论权重和一篇叙述性综述完全不同。

### 用标题词过滤（跨源通用）

不透传字段语法的源（crossref、openalex、semantic）靠标题词：

```
review · survey · "a review of" · "advances in" · "progress in"
perspective · commentary · "state of the art" · "current status" · outlook
```

中文源（`xueshu`）用：综述、述评、进展、研究现状、展望。

### 时间窗

先搜近 3 年。找不到就逐步放宽到 5 年、8 年，**并在报告里写明放宽到了哪一年**。一个多年无人综述的方向本身是信号：要么冷门，要么正在快速变化以至于没人敢总结，两种情况对读者的含义完全不同。

### 够了就停

2–4 篇高质量综述足够进入 B 阶段。综述搜到十几篇是在浪费——它们互相高度重叠，多出来的那些在 B 阶段的交集里体现不出增量。

---

## B. 从综述反查经典

**这是整个 skill 的核心机制。**

```bash
fastpaper cite <综述的DOI> --direction outgoing -n 30
```

返回该论文的参考文献列表。对 A 阶段找到的每篇综述各跑一次，然后**取交集**。

- 被 3 篇综述都引的 → 这个主题公认的奠基工作
- 被 2 篇引的 → 重要工作
- 只被 1 篇引的 → 可能是那篇综述的特定视角，不一定是共识

在报告里注明每篇经典**被几篇综述共同引用**。这个数字是协议层事实（真实引用边），比"引用数 12000"更能说明它在**这个主题**里的地位。

### 为什么不用 `--sort citations` 找经典

实测（v0.3.3）。同一条 query `wearable ECG myocardial infarction`，按引用排序：

| 源 | 返回的前几条 | 判断 |
|---|---|---|
| `crossref` | INTERHEART、2017 ESC 指南、MADIT-II、CARE 试验 | 全部跑题 |
| `openalex` | UK Biobank、心衰指南 ×2、房颤指南 | 全部跑题 |
| `semantic` | 心梗多导联分类、AI 检测、可穿戴心脏监护 | 保住了主题 |
| `pubmed` | `Error: pubmed cannot sort by citations` | 不支持，会报错，不会静默 |

crossref 和 openalex 在按引用排序时，相关性权重被压过了，返回的是**整个学科**的巨无霸。所以：

- **只在 `semantic` 上用 `--sort citations`**，而且是补漏，不是主路
- **crossref / openalex 上绝不这么用**
- `pubmed` 会明确报错，不用担心

## C. 最新进展（两轮）

综述有截止日期，之后的东西没人替你整理过。**这一阶段的检索式数量不得少于 A**——它是这份综述比已有综述新的唯一来源。

**时间锚点是今天，不是综述。** 一律 `--after <今年减 2>-01-01`。拿"最新那篇综述的年份"当起点是错的——综述停在 2019 年时 `--after 2019` 会捞回六年的东西，真正的前沿淹在里面。

### C1 —— 与 A 并行，不等任何人

三条入口，都不经过引用链：

```bash
# 1. 主题词，近两年
fastpaper search pubmed "<用户给的主题词>" --after <今年减2>-01-01 -n 10

# 2. 预印本——按定义不可能出现在任何已发表的综述里
fastpaper search biorxiv "<主题>" -n 8
fastpaper search medrxiv "<主题>" -n 8

# 3. 跨学科源——本学科的检索永远看不到他们
fastpaper search arxiv "<主题>" --field eess.SP --after <今年减2>-01-01 -n 8
fastpaper search arxiv "<主题>" --field cs.LG  --after <今年减2>-01-01 -n 8
```

第 3 条实测有效。拿一个纯临床主题（心电 + 心肌梗死检测）去 arxiv 搜：

```
[eess.SP] Self-Alignment Learning to Improve MI Detection from Single-lead ECG    2025
[cs.LG]   ECGLight: Compute-Light Framework For Paper ECG Digitization and MI     2026
```

作者是信号处理和机器学习的人，引的是他们那边的正典，PubMed 综述的引用网里根本没有他们。**反过来同理**：CS 主题要去 `pubmed` `europepmc` 搜，那边有大量用同一方法做临床验证的工作。

`dblp` 在这类自由文本检索上基本搜不到东西（它是题录库），别指望它。

### C2 —— A/B 之后，用新词重搜

**词汇会变，这是 C 必须分两轮的唯一理由。** C1 用的是用户给的词；读完 A 的综述和 B 的经典之后，你会看到一批**综述里没出现过的术语**——那往往就是新起来的子方向自己的叫法。用它们重搜：

```bash
fastpaper search <源> "<综述中未出现的新术语>" --after <今年减2>-01-01 -n 8
fastpaper search <源> "<问题词而非技术词>" --after <今年减2>-01-01 -n 8
fastpaper cite <C1 找到的新论文DOI> --direction incoming -n 20
```

**换问题词搜一轮。** 新入场者用自己的方法词汇，但描述的是同一个问题——搜结果/应用/临床终点的词，而不只是技术词。

**`cite --direction incoming` 要对 C1 找到的新论文做，不是对 B 的经典做。** 对经典做只会拿到本领域内部的发展；对新论文做才可能捞到刚跟进它的那批。注意这条仍在引用链上，所以它是补充，不是入口。

### 硬检查

**检查 1：C 一篇也没找到比最新那篇综述更晚的工作。** 两种可能，含义完全相反：

1. 这个方向确实停滞了 —— 是个该写进见解的结论
2. 你的检索词过时了 —— 换一批词再跑一轮

必须换词再试一次，然后在报告里明说是哪一种。直接写"未找到最新进展"而不做这一步，是把自己的检索缺陷当成了领域的现状。

**检查 2：前沿那批文献，是不是每一篇都能和 B 的经典连上引用边？** 如果是，说明断连的那批一篇也没搜到——跨学科源和预印本至少再各跑一轮。一个真正活跃的方向，前沿里总有一部分是从外面进来的。

预印本要**在正文里标明是预印本**，未经同行评议这件事读者有权知道。

## D. 引用热度与补漏

用户常问「哪些是历史上引用最多的」和「哪些最近在升温」。这是两个不同的量，
fastpaper 对它们的支持完全不同。

### 历史引用总数 —— 能直接拿

`openalex` 和 `semantic` 的 json 里有 `citations` 字段：

```bash
fastpaper search openalex "<主题>" -n 8 --format json     # 结果里每条带 citations
fastpaper get <DOI> --format json                          # 单篇的总引用数
```

这是协议层数字，不是估算。要按它排序，**只在 `semantic` 上用 `--sort citations`**
（见下面「必须避开的坑」里 crossref/openalex 跑题的实测）。

### 近期引用增速 —— 不要用 `cite` 去算

`cite` 只有 `--direction` 和 `-n`，**没有 `--sort`，没有日期过滤**，只能截断。
所以「拉一批 incoming 引用，数数其中近一年占多少」这个想法看着可行，实际不成立。

实测（v0.3.3）。取一篇总引用 280 的论文，同一个 id 拉不同数量的 incoming 边：

| `-n` | 2023 | 2024 | 2025 | 2026 | 2025 年占比 |
|---:|---:|---:|---:|---:|---:|
| 25 | 1 | 17 | 7 | 0 | **28%** |
| 60 | 5 | 29 | 26 | 0 | **43%** |
| 120 | 6 | 40 | 67 | 7 | **56%** |

**年份分布随 `-n` 系统性漂移**——返回的既不是随机样本，也不是按时间排序的样本。
用这种截断样本算出来的「引用增速」，测的是你填了多大的 `-n`，不是那篇论文的热度。
**不要写这种数字进报告。**

### 「什么在升温」的干净做法

不去算速度，改成**搜近期发表、且已经积累了引用的论文**：

```bash
fastpaper search semantic "<主题>" --after 2025-01-01 --sort citations -n 10
```

一篇 2025 年发表的论文已经拿到几十次引用，本身就是升温信号。这条路用的是
CLI 校验过的 `--after` 加排序，不碰引用边的抽样，没有截断偏差。

在报告里要如实描述它是什么：**「近 N 年发表且引用数居前的工作」**，
不要写成「引用增长最快的工作」——后者是你没有测量的东西。

## 必须避开的坑

### `CITED:>N` 不生效，要用 `CITED:[N TO *]`

fastpaper 的 SKILL.md 举的是 `CITED:>500`，但实测（v0.5.0）`>` 形式被 europepmc 静默忽略——阈值 500 和 100000 返回完全相同的结果。换成 Lucene 区间形式才真的过滤：

```
CRISPR AND CITED:>500          → 2 条
CRISPR AND CITED:>100000       → 2 条   ← 没过滤
CRISPR AND CITED:[500 TO *]    → 2 条
CRISPR AND CITED:[100000 TO *] → 0 条   ← 过滤了

递增验证：CITED:[0 TO *] 20 条 → [10000 TO *] 5 条 → [50000 TO *] 1 条
```

**用区间形式。** 这是唯一能在检索阶段按引用数筛的办法（`semantic --sort citations` 只能排序不能设阈值）。

### 通用技术：写在 query 里的过滤条件，换个极端值验一遍

CLI 的 flag（`--year` `--after` `--author`）由 fastpaper 校验，不支持会明确报错。但**写进 query 字符串的字段语法**（europepmc 的 `CITED:` `PUB_YEAR:` `OPEN_ACCESS:`、pubmed 的 `[pt]` `[mh]`、dblp 的 `year:`）是源端解析的，写错或不支持时多半**静默返回未过滤的结果**。

所以：**任何写进 query 的过滤条件，用一个极端值再跑一次。**

```bash
fastpaper search europepmc '<主题> AND PUB_YEAR:2024' -n 3     # 正常值
fastpaper search europepmc '<主题> AND PUB_YEAR:1800' -n 3     # 极端值，应该返回零条
```

极端值那次如果还返回结果，说明这个条件根本没生效。两次调用换掉一整类静默错误——比事后发现整份综述建立在未过滤的结果上便宜太多。

### 高引 ≠ 本主题重要

一篇论文的总引用数来自它的**所有**应用场景。UK Biobank 被引十万次，不代表它是可穿戴心电研究的经典。判断"在这个主题里重不重要"，靠的是被本主题的综述引用，不是全局引用数。

### 综述本身也要核验

综述最容易被当成可信来源直接抄。但它的二手转述可能失真、可能过时、可能有立场。**综述里的关键数字，要回到原始论文核对**，尤其是当那个数字会进你的正文时。

## 各源速查

| 源 | 出版类型过滤 | `--sort citations` | 适合 |
|---|---|---|---|
| `pubmed` | `[pt]` ✓ 最准 | 报错（安全） | 生医综述入口 |
| `europepmc` | 无可靠办法 | ✓ | 全文可得性好，`OPEN_ACCESS:y` |
| `semantic` | 无 | ✓ **唯一不跑题** | 补高引、跨学科 |
| `openalex` | 无 | ✓ 但**跑题** | 引用链（`cite` 的默认 DOI 路由） |
| `crossref` | 无 | ✓ 但**跑题** | 题录补全 |
| `arxiv` | 无 | 无 | CS/物理预印本，用 `--field` |
| `biorxiv` `medrxiv` | 无 | 无 | 生医预印本 |
| `xueshu` | 无 | 无 | 中文综述，**串行慢速** |

`fastpaper sources --capabilities` 是活的，拿不准就跑一次。
