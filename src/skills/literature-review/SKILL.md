# 文献综述

产物是**一份 Markdown 文件**，两部分：

1. **综述正文**（在最前）—— 可以整段粘进论文的连续散文，作者年份行内引用 + 文末参考文献列表。
2. **综述报告**（在后）—— 检索过程、文献图谱、核验结论、综述性见解。

正文放最前，是为了让你从文件开头选到分隔线就能直接粘走，不用在报告里手工摘。

**用用户说话的语言写。** 他用中文提问就出中文，用英文提问就出英文——正文、报告、小节标题全都跟着走。参考文献里的论文标题保持原文，不要翻译。

## 开工前

1. `date +%F` —— 文件名要用。
2. **定源，read 用得上的检索工具的 SKILL.md**（在 `<available_skills>` 里）。按 AGENTS.md「找论文」看这一轮要的文献落在哪 —— fastpaper、slowpaper，常常两个都要；主题要等第 4 步确认了才定得下来。fastpaper 各源检索语法和 filter 支持都不同，凭记忆猜 flag 会静默拿到错结果。
3. `ls papers/` —— 可能已经有现成的论文。
4. **确认主题**。用户给的是一句话主题、一个方向，还是一篇论文？给论文的话先 `fastpaper get <id>` 拿到它，用它的标题、摘要和参考文献作为检索起点。主题太宽（"人工智能在医学中的应用"）就用普通对话问清楚要收到哪一层，别自己挑一个。

## 问篇幅

检索开始前，用 `ask_user_question` 问一次篇幅档位（**必须单独调用**，不能和别的工具同批）：

| 档 | 字数 | 场合 |
|---|---|---|
| 短 | 800–1200 | 会议论文的 Related Work |
| 中 | 2000–3000 | 期刊论文的研究现状 |
| 长 | 4000–6000 | 学位论文的研究现状章 |

只问这一题。篇幅决定检索要铺多宽——长篇要 25–35 篇进正文，短篇 12–18 篇就够，先问再搜比搜完再删省事得多。

## 怎么跑检索命令

AGENTS.md 的「用工具的方式」全部适用：一次 bash 一条 fastpaper 命令，直接读 stdout，不建目录、不落中间文件（含 `-o`）、不写脚本归并。多条检索式用**多个并行调用**，不是 shell 循环。

只有两样东西该写进磁盘：`papers/` 里的 PDF，和最终那份文件。

**输出格式**：分诊扫标题用**默认 table**（`-n 8` 约 1.8k 字符，带 id/标题/年份/作者）；只有要精确比对字段时才 `--format json`（同样条数 ~20k，11 倍）。整轮开 json 是烧光上下文最快的方式。

## 第 1 步：检索

完整的检索战术、各源的能力差异、以及必须避开的坑，在 `references/search-strategy.md` —— **开始前先读它**。这里只给顺序和理由。

**只有 B 真的依赖 A**——要先有综述才能取它们参考文献的交集。找最新进展不依赖任何前序结果，所以不排队等：

```
A 找综述  ┐
          ├── 并行起跑
C1 最新进展第一轮（主题词 + 预印本）┘
     ↓
B 引用链反查经典（依赖 A）
     ↓
C2 最新进展第二轮（用 A/B 里没出现的新术语补搜 + cite incoming）
     ↓
D 引用热度与补漏
```

**为什么不是一上来就撒网搜主题词**：那会淹在几百条中等相关的结果里，而且分不出哪些是真经典——经典要靠 B 的引用链交集才认得出来。但这不构成让最新进展排队的理由。

**C 拆成两轮，是因为词汇会变。** C1 用用户给的词，C2 用 A/B 读完之后才知道的词——尤其是那些**在综述里没出现过的新术语**。一个刚起来的子方向如果换了叫法，只用老综述的词永远搜不到它。

> **两条线，互不依赖。** A+B 建立**共识地图**（这个方向公认的正典是什么），C 找**前沿**。
> 综述按定义是沉淀下来的东西，它不告诉你前沿在哪；用综述去定义"什么算新"是本末倒置。

### A. 先找综述

综述是建立共识地图的入口。一篇近三年的好综述已经替你做完了经典梳理，而且它的参考文献是**真实引用边**，比任何相关性排序都可靠。

目标：2–4 篇近 3 年的综述/评述/进展。找不到近三年的就放宽，并在报告里说明——一个多年无人综述的方向，本身是个值得写进见解的信号。

### B. 从综述反查经典

```bash
fastpaper cite <综述的DOI> --direction outgoing -n 30
```

拿到它的参考文献列表。**多篇综述的参考文献取交集**——被几篇独立综述反复引用的，就是这个主题公认的经典。

这条路比按引用数排序可靠得多。实测 `--sort citations` 在 `crossref` 和 `openalex` 上会严重跑题：搜 "wearable ECG myocardial infarction" 返回的是 INTERHEART、ESC 指南、UK Biobank——整个学科的巨无霸，跟主题无关。只有 `semantic` 保住了主题相关性。**"高引"是 proxy，"被本主题的综述反复引用"才是事实。**

**但要认清它的盲区：引用链只能找到与既有正典连着的工作。** 真正的新入场者常常是断连的——从别的学科带方法进来的人引的是他们那边的正典；换了一套术语的新子方向关键词和引用都对不上；预印本和工业界工作很多根本不进引用网。所以 **C 阶段绝不能依赖引用链**，它得有自己的入口。

### C. 最新进展（两轮，C1 与 A 并行）

综述有截止日期，之后的东西没人替你整理。**这一阶段的检索式数量不得少于 A 阶段**——它是这份综述比已有综述新的唯一来源。

**时间锚点是今天，不是综述。** 一律 `--after <今年减 2>-01-01`。用"最新那篇综述的年份"当起点是错的：综述停在 2019 年时，`--after 2019` 会捞回六年的东西，真正的前沿淹在里面。

**C1（与 A 并行，不等）**——三条入口，都不依赖引用链：

1. 用户给的主题词，近两年
2. 预印本 `arxiv` 与 `europepmc '<主题> AND SRC:PPR'`（bioRxiv / medRxiv 等都由 Europe PMC 收）—— 按定义不可能进任何已发表的综述
3. **跨学科源**：生医主题也去 `arxiv` 搜（`--field eess.SP` `cs.LG`），CS 主题也去 `pubmed` `europepmc` 搜。实测有效——同一个心电主题在 arxiv 上能搜到 2025–2026 年的工作，作者是信号处理和机器学习的人，引的是他们那边的正典，PubMed 综述的引用网里根本没有他们

**C2（A/B 之后）**：
- 从 C1 和 B 读到的新论文里挑出**综述中没出现过的术语**，用它们重搜
- 换**问题词**搜一轮，而不只是技术词——新入场者用自己的方法词汇，但描述的是同一个问题
- `fastpaper cite <近两年的新论文> --direction incoming` —— 注意是对**新论文**做，不是对经典做

**两条硬检查**：

1. **C 一篇也没找到比最新综述更晚的工作** → 不许就这么写"未找到最新进展"。要么方向确实停滞（该写进见解的结论），要么检索词过时。换一批词再跑一轮，报告里明说是哪一种。
2. **前沿那批文献如果每一篇都能和 B 的经典连上引用边** → 说明断连的那批没搜到。跨学科源和预印本至少再各跑一轮。

### D. 引用热度与补漏

**历史引用总数能直接拿**：`openalex` / `semantic` 的 json 里有 `citations` 字段。要按它排序只在 `semantic` 上用 `--sort citations`，**不要在 crossref / openalex 上这么用**。

**"近期引用增速"算不出来，别硬算。** `cite` 没有 `--sort` 也没有日期过滤，只能截断；实测同一篇论文（总引用 280），近一年引用占比在 `-n 25 / 60 / 120` 下分别是 28% / 43% / 56%——**分布随 `-n` 漂移**，算出来的是你填的参数不是论文的热度。

要回答"什么在升温"，改用：

```bash
fastpaper search semantic "<主题>" --after <前年>-01-01 --sort citations -n 10
```

近期发表却已积累引用，本身就是信号。报告里要如实叫它**"近 N 年发表且引用数居前的工作"**，不要写成"引用增长最快"——那是你没测过的东西。

### 边搜边记数

每个源跑了几条检索式、命中多少、去重后剩多少、筛出多少进核验。报告开头那行漏斗要用，**事后补不出来，当场记**：

> 源数 N1 → 检索式数 N2 → 命中 N3 → 去重后 N4 → **筛出进核验 N5** → 进入正文 N6；
> 全文 = **本轮新下 D1**（第 4 步两次 `ls papers/` 取差）+ **`papers/` 原有 D3** = N8

**动笔之前**核一遍：`N3 ≥ N4 ≥ N5 ≥ N6`、`N8 = D1 + D3`、`N8 ≤ N5`。这些数都在你边搜边记的对话里，
对不上就回去数清楚再写。**不要先写进文件、再回头 grep 着对** —— 一个数在报告里出现好几处，
改漏一处就前后矛盾。

## 第 2 步：文献图谱

六节，报告里直接用这些名字。空的一节也保留并写明"未找到"及搜了什么。

| 节 | 装什么 |
|---|---|
| **奠基与经典** | 这个方向从哪来。由 B 阶段的引用链交集得出，注明被几篇综述共同引用 |
| **已有综述与评述** | 别人已经总结过什么、各自覆盖到哪一年、彼此有无分歧。**这一节是文献综述特有的** |
| **主流路线与流派** | 按技术路线/方法学派分组，每组说清它的前提假设与适用边界 |
| **共识与争议** | 共识一条一行；争议**成对写**，谁对谁、分歧可能来自哪里 |
| **最新进展** | 近 2–3 年，尤其最新综述截止之后的。标出哪些还是预印本 |
| **空白与机会** | 没人做过或做得不够的。要具体到能被一句话证伪 |

「已有综述与评述」那一节最容易被忽略，但它决定你这份综述有没有存在价值：**如果已有一篇 2025 年的综述覆盖了同样的范围，你要说清楚自己补了什么**——是补了它之后的进展，是换了个组织角度，还是纳入了它没覆盖的分支。说不出来就要在见解里承认这一点。

## 第 3 步：核验

图谱里的每一篇、每一条论断，都要能指回真实来源。一份编造出来的综述比没有综述更糟，因为它看起来可信，而且会被原样抄进论文。

**存在性 + 元数据**：每篇 `fastpaper get <id>`，比对标题、年份、第一作者、期刊。

- 查不到 → 删掉
- 和你写的对不上 → 以回源为准修正，或删掉
- **两个源自己打架** → 并列呈现并说明，不擅自挑一个

**没有标识符的文献**（多数中文期刊论文、学位论文，从百度学术或 Scholar 找到的）`fastpaper get` 回不了源，「查不到就删」对它们不适用 —— 那是源的收录问题，不是论文不存在：

- 存在性以找到它的那个源为准：结果页上那条题录（标题、作者、刊名、年份）就是证据。题名在结果页被截断的，打开详情页补全，补不全就如实写「题名截断」
- 在报告里标「仅〈源名〉单源确认」，列进待核验清单；参考文献表里这一条不写 DOI，**一个都不许补编**
- 可以进正文。但只看到题录或摘要片段的，正文只写它研究了什么，不写它得出了什么结论

**论断**：正文里写下的每个具体结论（数字、方法、结论方向）都要能指到原文。`fastpaper read papers/<file>.pdf --section results --max-length 4000` 定段回原文比对。只读需要的段落。

拿不准有哪些节就先 `--list-sections`。要在全文里找某个说法（「作者承认了什么局限」「某个数字出现在什么上下文」），用 `--grep "<正则>" --context 500 --max-matches 10`——**别把全文倒出来自己翻**。拿不到全文的退回摘要，**在报告里**标注哪些只有摘要支撑——注意正文里不标，正文是要粘进论文的，不能带这种标记。

**边核边记两组数**：篇的层面（核验几篇 / 进正文几篇 / 剔除几篇及原因 / 几处元数据修正）；论断的层面（核对几条 / 几条全文比对 / 几条仅摘要 / 几条被修正或删除）。

## 第 4 步：下载

**写报告前再 `ls papers/` 一次**，和开工时那次取差，就是本轮新增的 D1。别凭记忆数自己发过几条 download 命令——换过源、先失败后成功的，记忆一定算错。

文件名规则：DOI 的 `/` 换成 `_`，arXiv id 和 PMC id 原样。

下载失败很常见（付费墙、反爬虫、返回落地页、无开放获取、源端限流，以及当年新发表、聚合源尚未收录）。**先看退出码**：`4` = 请求没问题、这个源就是没有，换个源才有意义；`2` = 命令写错了；`1` = 别的问题。`4` 之外，fastpaper 的错误会给出它试的 URL 和值不值得换源的判断——**照抄它的判断，别自己另起一套重试策略**。失败就在附录记「未获取」并写明原因。**不要编造下载成功。**

## 第 5 步：写正文

模板在 `assets/report-template.md`，用 `write` 写到**项目根目录**，文件名：

```
literature-review-<主题简称>-YYYY-MM-DD.md
```

主题简称用短横线连接的英文或拼音，别用空格、别用下划线、日期放最后——和 `research-ideation-*` 保持同一套样式，这样同一个课题目录下的产物能按类型排在一起。
**模板里两种引用块，别搞混。** 以 `〔写作指导〕` 开头的那些是写给你看的，**整块（到空行为止）都不进报告**，一条都不许留；其余 `>` 引用块——目前只有开头那条统计行——**是报告的一部分**，原样保留并把占位符填好。


正文部分的要求：

**它是连续散文，不是论文清单。** 判断标准很简单：如果每一段都是「X 等做了 A，Y 等做了 B，Z 等做了 C」，那是清单不是综述。综述要**把论文组织进一个论证**——按路线分组、指出它们共同的前提、说清谁解决了谁的问题、哪里仍有分歧。

**引用格式**：正文内用「作者 等（年份）」或 (Author et al., year)，跟正文语言走；文末参考文献列表按第一作者字母序，每条带完整题录和 DOI。

**参考文献表在动笔之前定。** 先定正文要引哪几篇，这份清单就是参考文献表 —— 正文与表一次写对，不靠写完之后拿作者名去文件里逐个对。

**不要出现这些**：`[仅摘要]` 标记、"本报告"、"我们检索了"、章节交叉引用（"见第二节"）、任何元信息。正文是要粘进别人论文的，带上这些就得手工删。

**结尾落到空白上。** 综述章的作用是给自己的工作腾出位置——最后一段要说清现有工作到哪儿为止、还缺什么。这一段往往是全篇被引用最多的。

**每一句都要有出处。** 没有文献支撑的概括（"近年来该领域发展迅速"）删掉，它对读者零信息量，还会在审稿时被要求补引用。

## 第 6 步：写报告

报告部分除了文献图谱，还要有一节**综述性见解**——这是你这份综述的增值所在，不是图谱的复述：

| 小节 | 要回答的 |
|---|---|
| **发展脉络** | 为什么是按这个顺序走过来的，每一步解决了上一步的什么问题 |
| **主要技术路线的前提假设** | 各条路线建立在什么假设上，哪个假设的证据最薄弱 |
| **现有综述的分歧及其指向** | 综述之间不一致的地方指向领域什么未解问题 |
| **发展瓶颈与趋势研判** | 哪条路线可能受限于什么瓶颈，哪个方向的条件正在成熟 |

这一节允许有判断和推测，但**每个判断都要挂在具体文献上**，并且明确区分"文献说的"和"我的推断"。

## 诚实边界

- **"下载最多"拿不到。** fastpaper 的源里没有一个提供下载量，只有引用数。不要用别的指标冒充，也不要说"广受关注"这种含糊话。
- **被引数只有部分源带**（哪些源带，以 `fastpaper sources --capabilities` 的 `citations` 列为准）。按 AGENTS.md「找论文」取 OpenAlex / Semantic Scholar 的，注明出自哪家；其余任何"重要性"判断都是 proxy，用了就标明。没有影响因子。
- **搜不到 ≠ 不存在。** 写清在哪些源、用哪些词没找到。
- **一个 id 都不许编。** 正文和参考文献里的每个 DOI 都必须 `fastpaper get` 回源确认过。做不到就不写那一条——正文会被原样抄进论文，一个假 DOI 就是一次学术事故。
- **只用纯 Markdown，不写 HTML 标签。** KyDog 的渲染器是 ReactMarkdown + remark-gfm，没有 rehype-raw，`<details>` 之类会原样显示。
