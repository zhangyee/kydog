# 论文精读与写作素材

服务**写作阶段**。产物是**一段话**——用户正在写的那一段，写完就粘进他的论文。

不是"这篇论文讲了什么"的摘要，那种东西 `fastpaper read` 加个模板就能生成，没有增量。

**只在对话里给那一段，不写文件。** 用户要的就是选中复制。原文依据表、批判性分析、精读记录，这些都不输出——真要核对，`papers/` 里有 PDF，回原文比回一张转述表更直接。

**用用户说话的语言写。**

## 和另外三个 skill 的分工

| | 输入 | 产物 |
|---|---|---|
| `/research-ideation` | 一个选题 | 选题站不站得住的评述 |
| `/literature-review` | 一个主题 | 领域综述 + 可粘的研究现状章 |
| `/research-frontier` | 一个方向 | 一年内动态的决策简报 |
| **`/paper-summary`** | **指定的论文** | **可粘进论文的那一段话** |

前三个都要靠检索去**发现**文献，也都写文件。这个两样都不做——论文是用户给的，产物是一段话。

## 开工前

1. `ls papers/` —— 用户给的论文可能已经在里面了。
2. **拿到论文**：看用户给的是什么，走对应的那条路（用到哪个检索工具，就 read 它在 `<available_skills>` 里的 SKILL.md）：

   | 用户给的 | 怎么拿 |
   |---|---|
   | DOI / arXiv id / PMID / PMC id | 先 `fastpaper get <id>` 确认是哪一篇，再 `fastpaper download <id> -d papers/` |
   | `papers/` 里的文件名 | 直接 `fastpaper read` |
   | 一个网页链接（出版社落地页、机构库、预印本页） | 用内置浏览器打开，从页面上的 PDF 链接 `browser_download`（slowpaper §五）。靠机构账号登录进去的订阅库不下载，只把链接报给用户 |
   | 只有题名（中文期刊论文、学位论文，没有 DOI） | 在百度学术上检索确认是哪一篇（量按 slowpaper 的代表作档），再去详情页找全文入口 |

## 全文是硬门槛

**没有全文做不了。** 摘要里没有方法细节、没有实验条件、没有作者承认的局限，而这些正是写作素材的来源。

下载失败时**先看退出码**：`4` = 这个源就是没有，换个源才有意义；`2` = 命令写错了；`1` = 别的问题。`4` 之外照 fastpaper 错误里给的判断办 —— 它说要真实浏览器才能过（出版社的人机挑战）时，就用内置浏览器打开那篇的落地页，从页面上的 PDF 链接 `browser_download`。

最终拿不到全文，**停下来问用户**（`ask_user_question` 必须单独调用）：你手动下载到 `papers/` 后我再继续 / 只用摘要做一段并标明 / 换一篇。

**不要默默用摘要顶上。** 用户拿去写论文的句子，如果实际来自摘要而他以为来自全文，是会出事的。

## 第 1 步：问要干哪个活

用户在命令里已经说了的（`/paper-summary <id> 帮我写相关工作`），直接照办，不要再问。没说才问。

`ask_user_question` **必须单独调用**，一题四选项：

| 活 | 产出的文字长什么样 |
|---|---|
| **写进相关工作** | 1–3 句成段文字，学术文体，带引用，可直接粘进 Related Work / 研究现状 |
| **写与它的对比** | 「与 X 等（年份）不同，本文……」这类句式，落点在**差异**而不在复述它 |
| **借鉴或复现它的方法** | 方法描述段 + 复现所需的关键细节，**并点明论文里没交代的那些** |
| **用它的局限论证必要性** | 「现有工作在 X 上受限……因此有必要……」这类过渡段，用于引出用户自己的工作 |

用户可以在选项之外自己写（工具带自由输入框）。

活是"写与它的对比"或"用它的局限论证必要性"时，你需要知道**用户自己的工作是什么**，否则写不出对比和过渡。他没说就用普通对话问——这是开放题，做成选择题会限制他。

## 第 2 步：精读

**先探结构，别猜**：

```bash
fastpaper read papers/<file>.pdf --list-sections
```

只请求列表里出现过的节。列表里没有 `abstract` / `introduction` 是常事——Nature 系期刊的摘要不带标题，这时读开头就是：`fastpaper read <pdf> --max-length 3000`。

按活选读哪几节：

| 活 | 重点读 |
|---|---|
| 写进相关工作 | abstract、introduction、conclusion |
| 写与它的对比 | methods、results —— 差异在细节里，不在摘要里 |
| 借鉴或复现方法 | methods 全部，results 的实验设置部分 |
| 用局限论证必要性 | discussion（作者自己承认的），results（数字撑不撑得住结论） |

**找具体说法用 `--grep`，不要把全文倒出来自己翻**：

```bash
fastpaper read papers/<file>.pdf --grep "limitation" --context 500 --max-matches 10
```

正则、默认大小写不敏感（`(?-i)` 区分大小写）。找作者承认的局限、找某个数字在什么条件下取得、找它怎么描述基线，都用这个。

### 批判着读——这决定那段话怎么措辞

不输出批判性分析，但读的时候必须留意下面这些，**因为它们直接改变你该用哪个词**：

| 留意什么 | 它怎么改变措辞 |
|---|---|
| 声称与证据的落差 | AUC 差 0.015 就写"略高于"，不写"高于"；只在点估计上占优、置信区间重叠，就不写"优于" |
| 指标是否匹配任务 | AUC 0.953 但固定阈值下灵敏度 67.7%，那句话不能只报 AUC |
| 基线是否公平 | 比较条件不一致的，要在句子里带上条件（"在同一测试集上"） |
| 数据划分与外部验证 | 只有内部划分的，不写"泛化到"，写"在该队列内" |
| 作者自己承认的局限 | 该带的限定要带上，别把作者自己都不敢说满的话写满 |

**宁可写弱一点也不要写过头。** 这段话会署用户的名字出现在他的论文里，写过头的代价是审稿意见，写弱一点没有代价。

## 第 3 步：写那一段

**判准只有一条：用户能不能整段复制粘贴进他的论文，一个字不改。**

- **学术文体，用用户的语言**，行内引用用「作者 等（年份）」或 (Author et al., year)
- **不出现任何元信息**：不写"本文认为"、"该论文指出"、"根据原文"这类转述框架
- **不出现页码、不出现标记**（`[仅摘要]` 之类），那些会被一起粘进论文
- **题名完整照录**，不许用省略号截断
- **多篇时织成一段**，不是一篇一句地罗列。写论文时多篇本来就是写成一段的：找出共同前提或共同缺口，用一条线索串起来

**每一个具体说法都要在原文里核到。** 核不到就从这段话里删掉——用户会把它原样放进自己的论文并署上自己的名字，一句核不实的话就是一次学术事故。这一步不出现在产物里，但必须做。

写完自己读一遍：这段话直接出现在一篇论文里，读者看得出是拼出来的吗？看得出就重写。

## 输出

**对话里只给那段话，前后什么都不要加。** 用户要选中复制，前后有字会连带选进去。

**不要写"核验状态：全部经全文核验"这类话。** 全部核验通过是应该的，说出来没有信息量，只是噪声。**沉默即正常。**

只有一种情况要开口：**有说法不是来自全文**（只有摘要支撑、或某处没能核到）。那时必须在段落之后单独说明是哪几条——这是安全底线，不能省。

不要复述读了哪些节、不要列原文依据、不要写文件。

## 诚实边界

- **那段话里的每一句都要经过原文核验。** 这是唯一不能松的地方——产物会被原样放进用户的论文。
- **拿不到全文就说拿不到**，不要用摘要顶替。
- **不做检索。** 需要背景、需要知道这篇后来被谁推翻了，那是 `/literature-review` 和 `/research-frontier` 的活。
