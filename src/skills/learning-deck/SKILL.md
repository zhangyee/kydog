# 知识自学报告

产物是**项目根目录下的一份 HTML 报告**，加上 `papers/` 里的 PDF。

HTML 不是为了交互（报告里一行 JS 都不许有），是为了**图和版式**：机制图内联 SVG、图注贴着图、依赖提示走侧注、方法对比走真表格、术语表两栏。

读者是**眼前这一个人**，不是泛泛的初学者。这份报告讲什么、跳过什么，由第 3 步的访谈决定——同一个主题，对不同的人该产出不同的报告。做不到这一点，这个 skill 就退化成了一篇百科条目。

**用用户说话的语言写。**

## 和另外五个 skill 的分工

| | 问题 | 读者预设 |
|---|---|---|
| `/research-ideation` | 我这个选题站不站得住 | 已经有想法的人 |
| `/literature-review` | 这个领域是什么 | 要写论文的人 |
| `/research-frontier` | 最近发生了什么 | 已在圈内的人 |
| `/fact-check` | 这句话成不成立 | 要下判断的人 |
| `/paper-summary` | 这篇论文怎么写进我的论文 | 正在写作的人 |
| **`/learning-deck`** | **这东西到底是怎么回事，我该怎么学** | **不在圈内，起点靠访谈测出来** |

**给的是一篇文章时两个 skill 都可能对**：想弄懂文章里那些看不懂的概念，是这个；想把这篇论文写进自己的相关工作，是 `/paper-summary`。拿不准就用普通对话问一句，别猜。

## 开工前

1. `date +%F` —— 报告文件名要用，你自己猜不准今天几号。
2. **read fastpaper 的 SKILL.md**（在 `<available_skills>` 里）。各源的检索语法和 filter 支持都不同，凭记忆猜 flag 会静默拿到错结果。
3. `ls papers/` —— 用户要问的那篇、或者该读的综述，可能已经在里面了。
4. **确认方向不是漫无边际的**。「人工智能在医学中的应用」这种粒度做不出自学报告——知识地图会摊成一张什么都沾一点的网，每个知识点都只能写三句话。太宽就用普通对话请用户收窄到一个能被一句话描述的主题、方法或概念。**这一步别用 `ask_user_question`**——这是开放题，做成选择题只会限制他。

## 怎么跑检索命令

AGENTS.md 的「用工具的方式」全部适用：一次 bash 一条 fastpaper 命令，直接读 stdout，不建目录、不落中间文件（含 `search -o`）、不写脚本归并结果。多条互不依赖的检索式用多个并行调用。

**分诊用默认 table，不要开 `--format json`。** `-n 8` 的 table 约 1.8k 字符，已经给了 id、标题、年份、作者，足够决定哪篇值得细看；同样条数的 json 是 ~20k，**11 倍**。只有要精确比对字段（核验元数据）时才开 json。整轮检索都开 json 是这个 skill 最容易把上下文烧光的地方——而它后面还要写一份带内联 SVG 的长 HTML。

**只有两样东西该写进磁盘**：`papers/` 里的 PDF，和最终那份 HTML 报告。知识图谱、访谈结果、候选文献清单都留在上下文里，不要为了「整理一下」先写个中间文件。

## 第 1 步：定标的（无中断）

`date +%F`。

**给的是一篇文章**（DOI / arXiv id / `papers/` 下的 PDF 路径都算）：先把它拿到手再说。

```bash
fastpaper get <id>                       # 确认是哪一篇
fastpaper download <id> -d papers/
fastpaper read papers/<file>.pdf --list-sections
fastpaper read papers/<file>.pdf --section introduction --max-length 4000
```

读它是为了**取出它依赖了哪些概念**——introduction 和 methods 里那些被当作已知直接用起来的术语，就是知识地图第二层的候选。不是为了总结这篇文章。

**给的是主题或方法**：直接进第 2 步。

## 第 2 步：第一轮检索 —— 找出「要讲哪些」

**这一轮的目标是知识点清单，不是证据。** 所以优先搜**综述、tutorial、primer 和奠基论文**，而不是最新进展。

**这一点和 `/research-frontier` 正好相反**：那个 skill 搜最近 12 个月、要的是尚未沉淀的东西；这个 skill 要的恰恰是已经沉淀下来的——教科书级的解释、被反复引用的原始论文、把一个领域讲清楚过一次的那篇综述。**别加 `--after`**，奠基论文常常在十年到三十年前。

```bash
fastpaper search semantic "<主题> review"            -n 10
fastpaper search semantic "<主题> tutorial"          -n 8
fastpaper search semantic "<主题> introduction primer" -n 8
fastpaper search semantic "<主题>" --sort citations  -n 10   # 高被引 ≈ 沉淀下来的
fastpaper search arxiv   "<主题>" --field <相邻类目>  -n 8
fastpaper cite <某篇综述的DOI> --direction outgoing  -n 20   # 综述引的就是这个领域的正典
```

最后那条最省力：**一篇好综述的参考文献表就是一张现成的知识点清单**，而 `cite --direction outgoing` 一次就能把它拉出来。

`--sort citations` **只在 `semantic` 上用**。在 `crossref` 和 `openalex` 上按引用排序会严重跑题（相关性权重被压过，返回的是整个学科的巨无霸）；`pubmed` 会明确报错。

**这一轮只扫标题和摘要，不下载。** 产出是一张 **2–3 层的候选知识图谱**：

- 顶层：目标概念（用户问的那个）
- 第二层：它直接依赖什么
- 第三层：第二层又依赖什么

这张图谱是第 3 步访谈的题库，也是最后 ② 知识地图那张 SVG 的底稿。第三层之后不用再往下——真需要，那是下一份 deck 的事。

## 第 3 步：三轮访谈

这一步是这个 skill 的全部价值所在。跳过它，产出就是一篇通用科普。

**`ask_user_question` 必须单独调用**，不能和别的工具放在同一批 tool call 里——`askBatchGuard` 会把整批拦掉，而且是**静默**的，你会以为自己问过了。一批里只有这一个工具调用，等回答，再发下一批。

**一层一轮，每轮 3–4 题，一题问一个知识点。** 每题三个选项，固定三档：

> **熟悉** / **听过但说不清** / **没接触过**

工具约束（违反会整批被拒）：一次 1–4 题，每题 2–4 个选项，`header` 不超过 12 个字符。选项之外用户可以自己写（工具带自由输入框），第一轮开始前告诉他这件事。

**别把三四个知识点塞进一题。** 回来的只有你写的选项 `label`（几个字的短标签），不带题干上下文；一题里混了几个概念，回来那句「听过但说不清」你分不清他在说哪个。

**下一轮问什么由上一轮的答案决定**：

- 标「熟悉」的分支**不再往下问**，也不进正文——它只在 ② 知识地图里作为「已掌握」的节点出现，链到术语表。
- 标「听过但说不清」和「没接触过」的分支**才往下钻**一层。前者往往比后者更值得写：他有残缺的图，纠正误解的收益最高。
- 三轮之后仍够不着的更前序概念**不再追问**，直接进报告的 ④ 前序速览，两三句话带过。科研工作者的知识底子参差不齐，把每条依赖链都问到根是对他耐心的浪费。

**用户跳过某题**：当未作答，按「听过但说不清」处理（把没验证过的东西当「熟悉」直接不讲，风险大得多），并在 ① 抬头的起点画像里如实说明这一项没答。
**用户关掉了提问**：这一轮就停，问他是想换个方式聊还是先搁置，不要自说自话把三轮替他答完。

访谈结果有三个去处，**每一处都要真的用上**，否则这一步白做：

| 访谈结果 | 落到报告哪里 |
|---|---|
| 整体起点 | ① 抬头那句「这份报告为谁而写」 |
| 每个知识点的档位 | ② 知识地图的节点三色 + ⑤ 写哪几节 |
| 标「熟悉」的那些 | ⑤ 各节的依赖侧注「本节假设你已经知道 §X」 |

最后一条是访谈数据最不显眼但最有用的用法：**读者卡住时，侧注告诉他往回翻哪。**

## 第 4 步：第二轮检索 —— 拿证据 + 拿图

访谈定下了要写哪几节，这一轮才**下载 PDF 到 `papers/`**。

**下载是必需的，不是可选的。** 重画 SVG 的前提是看懂原图；只读摘要画出来的图是编的，而一张编出来的机制图比没有图更糟——读者会拿它当真。

- **分 4–6 个一批**。实测一次并行 10 个 `download` 会在学到教训前全部失败（源端限流）。
- **先看退出码**：`4` = 请求没问题、这个源就是没有（没这篇 / 没 OA 副本），换个源或换个 id 才有意义；`2` = 命令写错了，改命令；`1` = 别的问题。**不要看到失败就一律重试**，退出码已经告诉你该不该。
- `4` 之外照 fastpaper 错误里给的判断办，别自己另起一套重试策略。
- 拿不到全文的**退回摘要**，并在 ⑪ 诚实边界里写明哪些论断只有摘要支撑。

**这个 skill 的全文获取率天然不低**：奠基论文和综述往往年代较早、OA 覆盖好，比 `/research-frontier` 那种搜最近 12 个月的场景有利得多。所以拿不到全文时先想想是不是换个源就有。

读全文的方式和别的 skill 一样，**先探结构再定段读**：

```bash
fastpaper read papers/<file>.pdf --list-sections
fastpaper read papers/<file>.pdf --section methods --max-length 4000
```

Nature 系期刊（Scientific Reports、Nature Communications）的 PDF 没有 `abstract` / `introduction` 标签，体例是 摘要 → Results → Discussion → Methods。列表里没有就读开头：`--max-length 3000`。

**要重画哪张图，就用 `--grep` 把讲那张图的地方捞出来**，别把全文倒出来自己翻：

```bash
fastpaper read papers/<file>.pdf --grep "Fig(ure)? ?1" --context 600 --max-matches 6
```

正则、默认大小写不敏感。图注 + 正文里第一次讲到它的那两段，通常就够你画出结构正确的示意图了。**画之前先问自己：这张图里每个框、每条箭头，我能在原文里指到出处吗？** 指不到就别画那一部分。

**每篇写进报告的文献都要 `fastpaper get <id>` 回源核验过**：比对标题、年份、第一作者。查不到就从报告里删掉；两个源打架就并列呈现，不擅自挑一个。

## 第 5 步：写报告

骨架是 `assets/report-template.html`。**照抄整份文件，把示例内容整段替换。**

那份示例讲的是扩散模型，纯属占位——它在那里是为了让你看见每种块长什么样、SVG 该画到什么程度。**写真报告时不要留下任何一句示例文字**，也不要把它的规模当配额：两节正文、三张图是那个例子的样子，你写几节由访谈定。

**开写前先完整读一遍模板**：它的头部注释写了四条会静默出错的硬约束，每个 `<section>` 的注释标了 ①–⑪ 和该填什么。

**所有样式都在模板那一个 `<style>` 里，不要自己造 class**——模板里没有的 class 名不会有任何样式，写出来的块看着就是一段裸文字。同理不要给正文加行内 `style`：正文行宽被限死在 32–36 个汉字是刻意的，撑开它就毁了长文档的可读性。

用 `write` 写到**项目根目录**：

```
learning-deck-<主题简称>-YYYY-MM-DD.html
```

主题简称用短横线连接的英文或拼音，别用空格。日期用开工时 `date +%F` 的结果。和 `research-ideation-*` / `literature-review-*` / `research-frontier-*` 同一套命名。

写完 KyDog 会出一张文件卡片，用户点一下就在 tab 里打开了，**所以不要在对话里复述报告内容**。只给三句话：

1. 这份报告的**起点画像**（基于访谈：你已经站在哪一层，所以我们只讲了哪几块）
2. **最该先读的那一节**，和为什么是它
3. **文件路径**

## 硬约束

前四条漏了会**静默出错**——报告照样写得出来，只是在 KyDog 里打开后不对劲，而你不会收到任何报错：

1. **不写 `<script>`。** 查看器用不给 `allow-scripts` 的沙箱 iframe 渲染，脚本一律不执行。要动效只能用 CSS animation 或 SVG SMIL（声明式，沙箱不拦）。
2. **不引任何外部资源**：没有 CDN、没有 `<link rel=stylesheet>`、没有 `@import`、没有网络字体、没有 `<img src="http…">`、CSS 里没有指向网络的 `url()`。所有样式在模板那一个 `<style>` 里，所有图内联 `<svg>`。
3. **所有外链写 `target="_blank" rel="noopener"`。** 沙箱不给 `allow-top-navigation`，普通链接点下去会试图在 iframe 里就地跳转。指向论文的 `<a href="https://…">` 是链接不是资源，允许；把它当资源加载（`img` / `link` / `@import`）不允许。
4. **颜色一律写成 `var(--ink, #2a2620)` 这种带 fallback 的形态**，变量名只能取自模板头部注释里的那份清单。写死颜色的报告在 midnight 主题下会瞎眼；用清单外的变量名则永远走 fallback，等于写死。

后三条是内容纪律：

5. **重画的图必须标「改画自 XX（年份）Fig.N」+ DOI 链接。** 并且**不允许把重画的示意图冒充实验结果图**——散点、热图、生存曲线这类数据图**不重画**，改成一张指路卡片：套 `.example` 块，`.tag` 写「原图」，一句话说明那张图给出了什么，配指向原文的外链。
6. **不建目录、不写脚本、不落中间文件**（含 `-o`）；**一个 DOI 都不许编**，每篇 `fastpaper get` 回源核验过。
7. **用用户说话的语言写。**

## 报告结构

三层同心圆：先给地图和路径，再补前序，然后是主体，最后收束与附录。模板里每一块都留好了位置和 class，这里是它们各自该装什么：

| | 块 | 装什么 |
|---|---|---|
| ① | 抬头 | 主题 / 日期 / 一句话「这份报告为谁而写」——**基于访谈的起点画像**，不是套话 |
| ② | 知识地图 | SVG。节点三色：已掌握 / 要重点补 / 一句话带过。**每个节点都是页内锚点**，兼作导航 |
| ③ | 速通路径 | 建议阅读顺序，每步一句「读完能回答什么问题」，带个时间估计 |
| ④ | 前序速览 | 访谈里他没掌握、但够不着重点的更前序概念，每个两三句话带过 |
| ⑤ | 知识点正文 | 主体。每个重点知识点一节，节内顺序固定（见下） |
| ⑥ | 方法对比表 | **主题是「某个方法」时才有**：它与 2–3 个替代方案的假设 / 适用场景 / 代价 / 失效情形 |
| ⑦ | 收束节 | 把上面这些点合起来回答「所以这个方法（这篇文章）到底在干什么」 |
| ⑧ | 术语对照表 | 中英对照 + 一句话解释 + 首次出现在哪节 |
| ⑨ | 建议下一步 | 该精读哪 2–3 篇（分必读 / 选读，每篇一句为什么）、该上手跑什么、下一个 deck 开什么 |
| ⑩ | 文献清单 | 题名 + DOI，全部回源核验过 |
| ⑪ | 诚实边界 | 见下面「诚实边界」一节 |

**⑦ 收束节不能省。** 读者读完要有一个「合起来」的时刻，而不是读完一堆零件——这是这份报告和一叠讲义的区别。

**⑤ 每一节的内部顺序是固定的**，不要自由发挥：

```
[节首] .lede 加粗的一句话定义（读者据此当场决定要不要细读这节）
       + .aside 依赖侧注「本节假设你已经知道 §X」（填访谈数据）
  → 它解决什么问题（**没有它之前大家怎么做**）
  → 机制：.with-figure 里放正文段 + <figure>（内联 SVG + figcaption）
  → .boundary 常见误解与边界
  → .source 出处（奠基论文 + 综述）
[节尾] .checkout「读完这节你应该能回答：…」+ .back 回知识地图的锚点
```

「它解决什么问题」那一段别写成背景介绍。**要写的是没有它之前人们怎么做、卡在哪**——一个概念只有在它解决的困难被讲清楚之后才立得住。

**每个重点知识点至少一张机制图。** 讲不动到要画图的程度，说明这一节还没想清楚，或者它本来就该并进前序速览。

## 学习导向的版式规则

上面讲的是报告**有哪些块**，这一节讲这些块的**功能**——帮读者定位、决定跳不跳、卡住时知道回哪去。这是「自学材料」区别于「好看的文档」的地方。**位置模板都留好了，你的活是把它们填满**，别让它们空着或者敷衍。

**入口与出口**

- 每节开头一句加粗的**一句话定义**（`.lede`）。它同时是 ⑤ 五段里的第一段——**不是额外再写一句**，两处指的是同一句。
- 每节结尾一句**「读完这节你应该能回答：…」**（`.checkout`）。我们不做需要 JS 的自测题，这句话起同样的作用且零成本。**问题要具体到能被回答**（「那个 √(1-β_t) 的缩放是干什么用的」），不是「你理解本节内容了吗」。

**卡住时的退路**

- 术语**首次出现处**加粗 + 加 `.term` 锚点链到 ⑧ 术语表；后文再提不再加粗。
- 依赖提示做成侧注（`.aside`）：「这节假设你已经知道 §2.1 的 X」。第 3 步的访谈数据正好填这个位置。
- 每节末尾一个回 ② 知识地图的锚点（`.back`），随时能重新定位。

**可读性**

- 正文行宽限死在 **32–36 个汉字**（约 65–75 拉丁字符）。模板已经限好了，**别用行内 style 或新容器把它撑开**。
- **图与讲它的那段不许分离**：图注紧跟图，图和相关正文段落一起放进 `.with-figure`，别让图漂到下一屏去。
- 例子块用 `.example`（配 `.tag`），和正文视觉上分开，扫读时能一眼跳过。

**位置感**

- 知识点标题带编号「第 3 / 7 个」（`.counter`）。长文档里缺少进度感是最主要的弃读原因。

**两条明确不做的**（写在这里是为了防止被当成漏做）：

- **折叠区块。** `<details>` 原生可用、不需要 JS，但折起来的内容在扫读和 ⌘F 里都消失了，对自学是负收益。
- **固定悬浮目录。** 要么挡正文，要么窄窗口下失效，而 ② 知识地图已经承担了导航职责。

## 诚实边界

⑪ 那一节不是免责声明，是读者判断这份报告能信到哪一步的依据：

- **搜不到 ≠ 没有。** 写清在哪些源、用哪些词没找到。自学报告的读者不在圈内，最没有能力自己识别缺口，所以这条在这里比在别的 skill 里更重要。
- **预印本要标明是预印本。** 未经同行评议这件事读者有权知道。
- **一个 id 都不许编。** 每个 DOI / arXiv id / PMID 都必须 `fastpaper get` 回源确认过。做不到就不写那一条。
- **重画的图必须标明是重画的**，并写清改画自哪一篇的第几张图。读者默认会以为图来自论文。
- **哪些论断只有摘要支撑、哪些是你的概括而非文献原话**，逐条列出来，别笼统写一句「部分内容基于摘要」。
