# 知识自学报告

产物是**项目根目录下的一份 HTML 报告**，加上 `papers/` 里的 PDF，
以及和报告同名的一份 `.learning-deck-<主题简称>-YYYY-MM-DD.json`——
报告的内容先写进那份 JSON，定死之后再渲染成 HTML，**JSON 交付后留着**（见第 5 步）。

HTML 是为了**图、版式与节奏**：机制图内联 SVG、图注贴着图、方法对比走真表格、
章节幕封页、方向键在节间跳转、逐条入场。

读者是**眼前这一个人**，不是泛泛的初学者。这份报告讲什么、跳过什么，由第 3 步的访谈决定——
同一个主题，对不同的人该产出不同的报告。做不到这一点，这个 skill 就退化成了一篇百科条目。

**用用户说话的语言写。**

## 这个 skill 分五册

SKILL.md 只讲流程与纪律。下面五册按需读，路径相对于 `<skill 目录>`——
从 `<available_skills>` 里本 skill 的 `<location>` 取（那是这份 SKILL.md 的绝对路径，
去掉末尾的 `SKILL.md` 就是）：

| 什么时候读 | 读哪一册 |
|---|---|
| **动手设计访谈题之前** | `references/interview.md` —— 题的形状、上限、三轮怎么递进、答案怎么落进报告 |
| **动手取图之前** | `references/figures.md` —— `fastpaper figures`、退出码分支、能力分支、内嵌与标注纪律 |
| **动手写 JSON 之前**（第 5 步全程） | `references/deck-json.md` —— JSON 形状、五种块类型、JSON→HTML 渲染对照表、JSON 层自检 |
| **动手往 JSON 里填正文之前**（最重要的一册） | `references/writing.md` —— 每个槽位该写成什么样，七条要求各配正反例 |
| **渲染之前 / 渲染后自检时 / 交付后用户要改结构时** | `references/layout.md` —— class 与组件清单、SVG 规矩、HTML 层的 grep 命令，以及「事后改结构：删一章 / 插一章 / 换顺序」 |

`assets/report-template.html` 是骨架，**渲染之前先完整读一遍**：
头部注释写了会静默出错的硬约束，每个 `<section>` 的注释标了 ①–⑩ 和该填什么。
**模板 `<body>` 里没有任何示例内容**（v5 起，理由见第 5.5 小步）——每一处等着你填的
位置都是一段带 `⟨待填⟩` 的注释；可以照抄的完整样例在 `references/layout.md`。

## 和另外五个 skill 的分工

| | 问题 | 读者预设 |
|---|---|---|
| `/research-ideation` | 我这个选题站不站得住 | 已经有想法的人 |
| `/literature-review` | 这个领域是什么 | 要写论文的人 |
| `/research-frontier` | 最近发生了什么 | 已在圈内的人 |
| `/fact-check` | 这句话成不成立 | 要下判断的人 |
| `/paper-summary` | 这篇论文怎么写进我的论文 | 正在写作的人 |
| **`/learning-deck`** | **这东西到底是怎么回事，我该怎么学** | **不在圈内，起点靠访谈测出来** |

**给的是一篇文章时两个 skill 都可能对**：想弄懂文章里那些看不懂的概念，是这个；
想把这篇论文写进自己的相关工作，是 `/paper-summary`。拿不准就用普通对话问一句，别猜。

## 开工前

1. `date +%F` —— 报告文件名要用，你自己猜不准今天几号。
2. **read fastpaper 的 SKILL.md**（在 `<available_skills>` 里）。各源的检索语法和 filter 支持都不同，凭记忆猜 flag 会静默拿到错结果。
3. `ls papers/` —— 用户要问的那篇、或者该读的综述，可能已经在里面了。
4. **确认方向不是漫无边际的**。「人工智能在医学中的应用」这种粒度做不出自学报告——知识地图会摊成一张什么都沾一点的网，每个知识点都只能写三句话。太宽就用普通对话请用户收窄到一个能被一句话描述的主题、方法或概念。**这一步别用 `ask_user_question`**——这是开放题，做成选择题只会限制他。

## 怎么跑检索命令

AGENTS.md 的「用工具的方式」全部适用：一次 bash 一条 fastpaper 命令，直接读 stdout，不建目录、不落中间文件（含 `search -o`）、不写脚本归并结果。多条互不依赖的检索式用多个并行调用。

**分诊用默认 table，不要开 `--format json`。** `-n 8` 的 table 约 1.8k 字符，已经给了 id、标题、年份、作者，足够决定哪篇值得细看；同样条数的 json 是 ~20k，**11 倍**。只有要精确比对字段（核验元数据）时才开 json。整轮检索都开 json 是这个 skill 最容易把上下文烧光的地方——而它后面还要写一份带内联 SVG 的长 HTML。

**只有三样东西该写进磁盘**：`papers/` 里的 PDF 与插图、`.learning-deck-<主题简称>-YYYY-MM-DD.json`、最终那份 HTML 报告。**后两样都是产物，不是中间文件**（JSON 交付后留着，理由见第 5 步）。除此之外的东西——知识图谱、检索的原始结果、候选文献清单——都留在上下文里，不要为了「整理一下」先写个文件。访谈结果不用另存：它会以每章的 `tier` 字段落进那份 JSON。

## 第 1 步：定标的（无中断）

**给的是一篇文章**（DOI / arXiv id / `papers/` 下的 PDF 路径都算）：先把它拿到手再说。

```bash
fastpaper get <id>                       # 确认是哪一篇
fastpaper download <id> -d papers/
fastpaper read papers/<file>.pdf --list-sections
fastpaper read papers/<file>.pdf --section introduction --max-length 4000
```

**已经在 `papers/` 里的直接从 `--list-sections` 那两行开始**，前两条不用跑。

读它是为了**取出它依赖了哪些概念**——introduction 和 methods 里那些被当作已知直接用起来的术语，就是知识地图第二层的候选。不是为了总结这篇文章。

**给的是主题或方法**：直接进第 2 步。

## 第 2 步：第一轮检索 —— 找出「要讲哪些」

**这一轮的目标是知识点清单，不是证据。** 所以优先搜**综述、tutorial、primer 和奠基论文**，而不是最新进展。

**这一点和 `/research-frontier` 正好相反**：那个 skill 搜最近 12 个月、要的是尚未沉淀的东西；这个 skill 要的恰恰是已经沉淀下来的——教科书级的解释、被反复引用的原始论文、把一个领域讲清楚过一次的那篇综述。**别加 `--after`**，奠基论文常常在十年到三十年前。

```bash
fastpaper search semantic "<主题> review"            -n 10
fastpaper search semantic "<主题> tutorial"          -n 8
fastpaper search semantic "<主题> introduction primer" -n 8
fastpaper search semantic "<主题>" --sort citations  -n 10   # 高被引 ≈ 沉淀下来的
fastpaper search arxiv   "<主题>" --field <相邻类目>  -n 8
fastpaper cite <某篇综述的DOI> --direction outgoing  -n 20   # 综述引的就是这个领域的正典
```

最后那条最省力：**一篇好综述的参考文献表就是一张现成的知识点清单**，而 `cite --direction outgoing` 一次就能把它拉出来。

`--sort citations` **只在 `semantic` 上用**。在 `crossref` 和 `openalex` 上按引用排序会严重跑题（相关性权重被压过，返回的是整个学科的巨无霸）；`pubmed` 会明确报错。

**这一轮只扫标题，不下载。** 产出是一张 **2–3 层的候选知识图谱**：

- 顶层：目标概念（用户问的那个）
- 第二层：它直接依赖什么
- 第三层：第二层又依赖什么

这张图谱是第 3 步访谈的题库，也是最后 ② 知识地图那张 SVG 的底稿。第三层之后不用再往下——真需要，那是下一份 deck 的事。

## 第 3 步：三轮访谈

**这一步是这个 skill 的全部价值所在。跳过它，产出就是一篇通用科普。**

**动手设计题目之前先读 `references/interview.md`。** 那里有题的形状（一题一个知识点、
三个选项是掌握程度的三档、单选）、开场白怎么说、三轮怎么递进、答案怎么落进报告。

流程层面只有三件事写在这里：

1. **`ask_user_question` 必须单独调用**，不能和别的工具放在同一批 tool call 里——
   整批都会被拦下。一批里只有这一个工具调用，等回答，再发下一批。
2. **一题问一个知识点，问得多**：每轮最多 10 题、三轮最多 30 个知识点，用满是正常的。
   第 1 轮的第一题问**想学到哪一档**（看懂 / 能自己走一遍 / 能在它上面改），
   只问学习深度，不问课题规划——那是 `/research-ideation` 的事。
3. **下一轮问什么由上一轮的答案决定。** 三轮题目一开始就写死，等于没访谈。

## 第 4 步：第二轮检索 —— 拿证据 + 拿图

访谈定下了要写哪几节，这一轮才**下载 PDF 到 `papers/`**（第 1 步那篇除外——用户点名的那篇一开始就要读，不等访谈）。

**下载是必需的，不是可选的。** 重画 SVG 的前提是看懂原图；只读摘要画出来的图是编的，而一张编出来的机制图比没有图更糟——读者会拿它当真。

- **分 4–6 个一批**。实测一次并行 10 个 `download` 会在学到教训前全部失败（源端限流）。
- **先看退出码**：`4` = 请求没问题、这个源就是没有（没这篇 / 没 OA 副本），换个源或换个 id 才有意义；`2` = 命令写错了，改命令；`1` = 别的问题。**不要看到失败就一律重试**，退出码已经告诉你该不该。
- `4` 之外照 fastpaper 错误里给的判断办，别自己另起一套重试策略。
- 拿不到全文的**退回摘要**，并在 ⑩ 诚实边界里写明哪些论断只有摘要支撑。

**这个 skill 的全文获取率天然不低**：奠基论文和综述往往年代较早、OA 覆盖好，比 `/research-frontier` 那种搜最近 12 个月的场景有利得多。所以拿不到全文时先想想是不是换个源就有。

读全文的方式和别的 skill 一样，**先探结构再定段读**：

```bash
fastpaper read papers/<file>.pdf --list-sections
fastpaper read papers/<file>.pdf --section methods --max-length 4000
```

Nature 系期刊（Scientific Reports、Nature Communications）的 PDF 没有 `abstract` / `introduction` 标签，体例是 摘要 → Results → Discussion → Methods。列表里没有就读开头：`--max-length 3000`。

**要重画哪张图，就用 `--grep` 把讲那张图的地方捞出来**，别把全文倒出来自己翻：

```bash
fastpaper read papers/<file>.pdf --grep "Fig(ure)? ?1" --context 600 --max-matches 6
```

正则、默认大小写不敏感。图注 + 正文里第一次讲到它的那两段，通常就够你画出结构正确的示意图了。**画之前先问自己：这张图里每个框、每条箭头，我能在原文里指到出处吗？** 指不到就别画那一部分。

**同一批里把原文插图也取下来**：

```bash
fastpaper figures <id> -d papers/
```

**动手之前先读 `references/figures.md`**——退出码分支（`4` 和 `1` 都不重试）、
文件名与图号不对应、`.pdf` 走 `pdf_figure_to_png`、`.eps` 跳过、
**能不能插原图取决于当前模型看不看得见图**，还有内嵌与标注的纪律，全在那一册。

**每篇写进报告的文献都要 `fastpaper get <id>` 回源核验过**：比对标题、年份、第一作者。查不到就从报告里删掉；两个源打架就并列呈现，不擅自挑一个。

## 第 5 步：写报告（六小步）

**内容先进 JSON，定死之后再渲染成 HTML。** 分六小步，不要合并、不要跳。

为什么绕这一趟：报告的正文本来就得你自己写，而**在两千行 HTML 上边想边写**，
每改一次都得把整篇正文再来一遍——「拼好一次写回」于是永远比逐节匹配 `oldText` 省力。
三次真跑里 agent 三次绕过 `edit` 去整篇重写（一次 perl、两次 python），根子在这里。
JSON 把「想清楚内容」和「变成 HTML」切开：**5.1–5.4 全程不碰 HTML**，改一章只是改几行；
5.5 的内容已经定死，照对照表贴就完了，**只有图要在那一步现画**。

**动手之前先读 `references/deck-json.md`**——JSON 的形状、五种块类型、
以及渲染对照表都在那一册。它规定的一条最要紧：`html` / `intro` / `aside` 这些字段是
**字符串数组，每个元素就是渲染后 HTML 里的一行，连缩进都一样**，渲染时原样贴。

这条不是洁癖，它是「渲染完了还要改」这件事能便宜下来的全部原因：
改一段话就是**在 JSON 上 `edit` 一行，再拿同一个 `oldText` / `newText` 在 HTML 上
`edit` 一次**——第二次是第一次的复制粘贴。1 次改动变 2 次，不是 1 次变 20 次。
只有加块 / 删块 / 换顺序这种结构变动才要重渲一章，而那也只是一百来行。

⚠️ **SVG 不进 JSON。** JSON 里每张图只写「画什么」（`figure` 块的 `sketch` 字段、
② 知识地图的 `map.sketch`），**标记本身到 5.5 才写出来**。
理由：5.1–5.4 要定的是内容，没人会审 SVG 标记的教学价值；而 SVG 是整份报告里最贵的
一块，进 JSON 就意味着它被写两遍（一遍转义进 JSON、一遍贴进 HTML），
正好在最贵的地方违背了「切开」的初衷。代价一并记着：**光靠 JSON 重渲不出原来那张图。**

### 5.1 写 JSON 骨架

- **输入**：第 2 步的知识图谱、第 3 步的访谈档位、第 4 步的文献与图。
- **产出**：`<项目根>/.learning-deck-<主题简称>-YYYY-MM-DD.json`，只有骨架。
- **怎么做**：`write` 一次建出来。**这是全程唯一一次对 JSON 用 `write`，之后只用 `edit`。**
  骨架里顶层字段（`title` / `date` / `forWhom` / `glossary` / `references` …）可以先写空，
  但每章的 `number` / `id` / `title` / `lede` / `tier` 现在就要写实，`blocks` 留 `[]`。
- **衔接**：这份骨架就是 5.2 要核的东西。

主题简称用短横线连接的英文或拼音，别用空格；日期用「开工前」那次 `date +%F` 的结果。
HTML 报告用同一个简称同一个日期，和 `research-ideation-*` / `literature-review-*` /
`research-frontier-*` 同一套命名。

#### 顺手把 `hero` 定下来（抬头那条封面带用哪个方向）

顶层 `hero` 字段三选一：`gridwave` / `constellation` / `holoband`（三个画面长什么样见
`references/deck-json.md` 的 `hero` 那一节）。

**由 slug 查出来，不许自己挑。** 「自己挑一个」的实际结果是每份报告都挑第一个，
那就等于没有这个字段。查法是两次查表 + 一次交叉，纯机械，不用数数、不用算：

**第一步**，取 slug 的**前两个字母/数字**（跳过连字符），各查一次桶号：

| 桶号 | 字母 | 数字 |
|---|---|---|
| **0** | a d g j m p s v y | 0 3 6 9 |
| **1** | b e h k n q t w z | 1 4 7 |
| **2** | c f i l o r u x | 2 5 8 |

**第二步**，用「第一个字符的桶号」查行、「第二个字符的桶号」查列：

| | 第二=0 | 第二=1 | 第二=2 |
|---|---|---|---|
| **第一=0** | `gridwave` | `constellation` | `holoband` |
| **第一=1** | `constellation` | `holoband` | `gridwave` |
| **第一=2** | `holoband` | `gridwave` | `constellation` |

例：`ecg-fm-ami-2026-08-21` → 前两个字符 `e`、`c` → 桶 1、桶 2
→ 第 1 行第 2 列 → **`gridwave`**。

⚠️ **取的是前两个字符，不是末尾**。slug 末尾永远是日期的数字，拿末尾查等于按日期
分脸——同一天做的报告会全都长一样。前两个字符落在主题简称里，跟日期无关。
（用一组 35 个真实形态的 slug 试过这张表：三个方向 13 / 12 / 10，没有一边倒。
换成「首字母 + 末字母」是 18 / 11 / 6 —— 英文与拼音的词尾扎堆在 s / g / n 上。）

⚠️ **不许运行时随机。** 这个值写死在 JSON 与 HTML 里，**同一份报告重新打开必须还是
同一张脸**。用户想换，改 `hero` 与 HTML 里 `data-hero` 那两处就行（见 5.5）。

### 5.2 自核 TOC，把提纲打出来

- **输入**：5.1 的骨架。
- **产出**：一份定死的章节序列，外加打在对话里的一份提纲。
- **衔接**：**自核完直接进 5.3。这一步不提问、不等待、不设闸门。**

⚠️ **这里没有确认停顿（用户决定）。** 早先的版本在这里停下来问用户三件事。
第五次真跑的实测：走到这一步之前已经处理了 **283 秒**——人早把窗口切走了，
**在一个已经切走的窗口里提问等于没问**，只是让流程白等一轮。
停顿当初的立论是「TOC 在这里定死最便宜」，而那个便宜现在由 5.5 的**逐章渲染**提供了：
回 JSON 改一章、只重渲那一章。**取消停顿不是放弃校准，是校准挪到了交付之后**——
所以 5.6 交付的那条消息必须写清怎么改，改结构的走法见
`references/layout.md`「事后改结构：删一章 / 插一章 / 换顺序」。

**先自核三件事。这三件是你的活，不是用户的活——取消停顿之后更是：不会有第二个人替你看。**

1. **覆盖**——访谈里标「没接触过」「听过但说不清」的知识点全都有着落了吗？
   要么成一章，要么收进 ④ 前序速览，一个都不许掉在地上。
2. **顺序**——逐章问一遍「读到这一章，它依赖的东西前面讲过了吗」。没讲过就换位置或补一章。
3. **粒度**——有没有一章顶别的三章？有没有一章薄到该并进 ④？

**任何一条不过关，回 5.1 自己改掉，不要拿去问用户。**
顺序、覆盖、粒度是专家判断，你手上有第 2 步的知识图谱和第 4 步的文献，本来就该你来判断。
用户跑这个 skill 正是因为他不懂这些——刚问完他「这些你不懂」，
转头请他评审这些内容的教学结构，是把自己该做的判断推给了最不适合做的人。

**自核过了，把提纲打出来。这是给他留个底，不是评审，也不是等他点头。**
零成本，而且他回头翻对话就看得到当时定的是什么，不必去开 JSON。

关键在**每章都要接回他自己在访谈里说过的话**：一串他没见过的术语，他回头扫一眼
也看不出这是不是他要的东西；用他自己的语言呈现，他扫一眼就知道。所以每章三行：

```
§3 归一化：按导联还是按整条记录
   你说过 · 「z-score」那题你选的是：知道是减均值除以标准差，但没想过统计范围不同会带来什么差别
   这一节就讲 · 三种统计范围各自算出什么、为什么跨中心的数据必须按导联来
```

中间那行的规矩，比章节标题本身要紧：

- **原样用他当时读到并选中的那句选项描述**，不要换成你的措辞。
  更不要写成「档位：听过但说不清」——档位名是我们内部的标签，他没见过这三个词。
- **他在选项外自己写的答案，加引号原样照抄**，那是最值钱的一条：
  `你说过 · 你写的是「我只在 MIT-BIH 上跑过，换个数据集就崩」`。
- **他没被问到的章**（第 3 轮之后你自己补的前序依赖）如实标出来，别硬编一句他没说过的话：
  `你说过 · 这个没问到 —— 它是 §5 的前提，我判断得先讲`。
- **他跳过没答的题**按 `references/interview.md` 当「听过但说不清」处理，那一行也写实：
  `你说过 · 这题你跳过了，我按「听过、说不清」办`。

**收尾一句话，陈述句，说完就接着干：**

> 上面是这份报告的提纲，一共 N 章、读完约 M 分钟。我按这个往下写。

- **这段话后面不许挂问题。** 「有哪一章你用不上吗」「篇幅合适吗」「还有什么想弄明白的」
  ——一条都不要留。挂了也不会有人在那里回答，只会让你自己以为该停下来等一等。
  **收尾那句写完，下一个动作就是 5.3 的第一次 `edit`。**
- **不许用 `ask_user_question`，也不许用任何别的方式停下来等。**
- **用户中途自己插话提了意见**，那就照办：回 5.1 的文件上改掉再往下走。
  那是他主动给的，不是你问来的——两件事别混。

### 5.3 逐章把内容填进 JSON

- **输入**：5.2 定死的骨架。
- **产出**：内容填满的 JSON——每章的 `aside` / `blocks` / `boundary` / `source` /
  `checkout`，以及顶层那些还空着的槽位。
- **怎么做**：**一章一次 `edit` 调用。** `oldText` 取那一章从 `"id": "c3",` 到
  `"blocks": []` 的那五行（`id` / `title` / `lede` / `tier` / `blocks` 连着，
  在整个文件里天然唯一），`newText` 是同样这几行、把 `blocks` 换成填好的内容、
  后面接上 `boundary` / `source` / `checkout`。一次调用里可以有多条 `edits[]`，
  但**不要跨章合并**——一章一次，出错了只有这一章要重来。
- 章节全部填完之后，再补顶层的 `map` / `primer` / `compare` / `summary` /
  `glossary` / `next` / `references` / `honesty` / `forWhom`——它们要等章节定了才写得准
  （知识地图的节点要指向真实的章号，术语表要覆盖正文真的用到的词，
  `references[].id` 要覆盖每章 `source[]` 里引到的每一篇）。
  **`readingMinutes` 放到最后算**，算法见 `references/deck-json.md`。
- **写之前读 `references/writing.md`**（最要紧的一册：v1 槽位一个不缺、格式完全合规，
  读起来却像审稿人清单，差的就是那七条），块类型与字段查 `references/deck-json.md`。
- **图在这一步只写意图，不写 SVG。** `figure` 块的 `sketch` 说清三件事：
  `form`（骨架是时间轴 / 流程链 / 对照两栏 / 分层框图……）、`elements[]`
  （图上有哪些东西、各自身上那行字、彼此什么关系，4–8 条）、
  `emphasis`（最要紧的那一处和它为什么要紧）。② 知识地图的 `map.sketch` 同理，
  外加 `nodes[]` / `edges[]`。字段的粒度和两个边（太粗 / 太细）见
  `references/deck-json.md` 的「`sketch`：这张图画什么」。
  **一个尖括号都不要写进 `sketch`**——坐标、颜色、class、viewBox 全归 5.5，
  在这里写等于用中文重打一遍 SVG。
- **衔接**：全部填完再进 5.4，不要边填边核。

### 5.4 核 JSON 内容

- **输入**：填满的 JSON。
- **产出**：过了自检的 JSON。**到这一步 HTML 还不存在，一张 SVG 也还没画。**
- **怎么做**：把整份 JSON 读一遍（它小到读得完），跑 `references/deck-json.md`
  的「JSON 层自检」6 组，再按 `references/writing.md` 第 9 条人读一遍。
- **图在这一步核的是「值不值得画、画的对不对」**，不是标记：每章有没有图（J-B 6）、
  图号连不连续（J-B 10）、出处标了没（J-B 7）、`sketch` 三个字段全不全（J-B 8）、
  `sketch` 里有没有混进画法（J-B 9）。再人读一遍 `emphasis`——
  **它说不出这张图在讲机制的哪一步，这张图就还没想清楚，退回 5.3 重想，别留到 5.5 现编。**
- **衔接**：不过关就回 5.3 改那一章——**改的是几行 JSON，不是几百行 HTML**。
  全过了才进 5.5。

### 5.5 `cp` 模板，逐章渲染

- **输入**：过了自检的 JSON + `assets/report-template.html`。
- **产出**：`<项目根>/learning-deck-<主题简称>-YYYY-MM-DD.html`。
- **怎么做**：

```bash
cp <skill 目录>/assets/report-template.html <项目根>/learning-deck-<主题简称>-YYYY-MM-DD.html
```

**先 `cp` 出一份，再在拷贝上改。不要用 `write` 从零重打一份。** 让模型逐字重新生成
这么大一份文件，典型结果是样式块被省略或改写（写成 `/* 样式同模板 */`、合并规则、
丢掉媒体查询），而**丢一条 CSS 规则不会报错，只是打开后版式不对**。
**`<style>` 与文末 `<script>` 两块原样不动，一个字都不要改、不要重打**；
`<body>` 里那条 `div.hero-band`（抬头的深色封面带，排在 `<div class="deck">` 之前）
也**整块原样保留**，它是纯装饰层——**唯一要改的是 `data-hero` 那一个值**，
填 JSON 的 `hero`（见 5.1）。**别删它**：抬头三行字用的是带上那套浅色，
带没了标题就是浅色压在浅纸上，看不见而且不报错。

**这一步有一件事不是「贴」：画图。** JSON 里每张图只有 `sketch`（画什么），
SVG 标记在这里才写出来——`form` 定骨架、`elements[]` 定画哪些东西和各自身上那行字、
`emphasis` 那一处套 `.svg-hi`。**怎么画照 `references/layout.md`「画 SVG」那一节**
（viewBox 宽 640、图内字号不低于 12、颜色只用模板的 class、每张图自带一套 `<defs>`），
别自己另立一套。`sketch` 本身一个字都不进 HTML。

⚠️ **画不出来就说明 `sketch` 没写够，回 5.3 补写它，再回来画**——
不要在这里凭空补构思，那等于这张图的内容从没被 5.4 审过。

⚠️ **模板 `<body>` 里没有任何示例内容（v5，用户决定）。** 每一处等着你填的位置
都是一段带 `⟨待填⟩` 的注释；**每一处都必须被一次 `edit` 消费掉**，没有例外、
也没有「照抄改几个字」这条便宜路。

为什么改成这样：v4 的模板自带两个示例章节的壳，这一步的指令是「第 1、2 章用掉那两个
壳，第 3 章起用插入」。**两条路的价钱差得太远**——插入的 `oldText` 只有一行注释，
替换壳的 `oldText` 含八十行示例 SVG。第四次真跑的结果是九章全走了插入这条便宜路，
两个壳原地留在文件里：JSON 里 9 章，HTML 里 11 个幕封页，目录跟正文对不上，
全篇残留 41 处示例文字。**同一个错误第三次出现，根子都是同一件事：留了一条能跳过
必做工作的便宜路。** 现在没有壳可用，插入是唯一的路，也就没有东西可泄。

按这个顺序 `edit`，每一步照 `references/deck-json.md` 的渲染对照表贴，
可以照抄的完整样例在 `references/layout.md`：

0. **一次 `edit`**：`<body>` 开头 `div.hero-band` 的 `data-hero`，填 JSON 的 `hero`
   （单独一次，因为这块在 `<div class="deck">` 之前，跟下面那次不相邻）。
1. **一次 `edit`**：`<nav class="toc">` 里 `.toc-sub` 的知识点条目
   + ① 抬头的 `h1` / `p.meta` / `p.for-whom`。
2. **一次 `edit`**：② 知识地图（照 `map.sketch` 现画那张 SVG）+ ③ 前序速览。
3. **章节，一章一次 `edit` 调用**：`oldText` 是那一行
   `<!-- ④-ANCHOR 知识点章节插在这一行之前 ⟨待填⟩ -->`，
   `newText` = 这一章的「幕封页 + `.concept`」一对 + 同一行注释。
   **插最后一章时不再带回那行注释**——锚点用完就该消失，它带着 `⟨待填⟩`，
   留下来会被 5.6 的自检 H1 抓到。
4. **⑤ 的处理放在所有章节插完之后**：`compare` 有内容就填它，
   `compare` 是 `null` 就把 ⑤ 整节连同目录里那条「方法对比」一起删掉。
5. **一次 `edit`**：⑥ 总结、⑦ 术语对照、⑧ 建议下一步、⑨ 参考文献、⑩ 诚实边界。

⚠️ **⑨ 参考文献要先于正文的 `source[]` 想清楚 id**：正文引用现在是**两跳**
（正文 `<a href="#r-xxx">` → ⑨ 那条 `<li id="r-xxx">` → 论文原 URL），
第 2、3 步贴出去的 `source[]` 指的就是第 5 步那些 id。漏一个就是一个点了不动的
死链接，H4 会抓。写法见 `references/layout.md`「⑨ 参考文献与两跳引用」。

- **衔接**：渲染完进 5.6。渲染中发现某章**内容**不对，**回 JSON 改**（见硬约束第 6 条），
  不要在 HTML 上就地改主意。**图的画法**（框排不下、线画歪了、class 用错）是例外，
  就在 HTML 上改那张 `<svg>`——JSON 里本来就没有画法。

### 5.6 HTML 层自检，然后交付

- **输入**：渲染好的 HTML。
- **产出**：可以交付的报告。
- **怎么做**：跑 `references/layout.md`「交付前自检 · HTML 层」那 4 组命令，
  **跑一次**——结构类的判据 5.4 已经在 JSON 上核过了，这里只查渲染后才成立的那几条。
  有命中就回 JSON 改、重贴那一处，然后**只重跑命中的那一组**。
- **`.learning-deck-*.json` 留在项目里，不要删。** 它和报告并排放着：以后模板改进了
  可以拿它重渲，用户想改一句话也不必重跑访谈与检索。KyDog 的文件树不显示点号开头的
  文件，它不会挤占左侧那棵树。

**不要在对话里复述报告内容**——它已经在文件里了，写完会出一张可点击的文件卡片，点了直接打开，用户也可以在左侧文件树里双击那个 `.html`。只给四句话：

1. 这份报告的**起点画像**（基于访谈：你已经站在哪一层，所以我们只讲了哪几块）
2. **最该先读的那一节**，和为什么是它
3. **文件路径**
4. **要改怎么改**——一句话说清「先改 JSON，再改对应的 HTML」，
   并且**把 JSON 的路径写出来**（`.learning-deck-<主题简称>-YYYY-MM-DD.json`，和报告并排）。

⚠️ **第 4 句不许省。** 5.2 不再停下来问提纲之后（见那一小步的说明），
**交付这条消息是唯一的校准入口**。改法写在 SKILL.md 里不算数——用户不会去翻 skill，
他手上只有你这条消息。KyDog 的文件树也不显示点号开头的文件，路径不写他找不到那份 JSON。

一个可以照着改的样子（把简称与日期换成真的）：

> 要改的话直接跟我说。报告的内容都在 `.learning-deck-ecg-fm-ami-2026-08-21.json` 里，
> 改一句话是先改这份 JSON、再把同一处改进 HTML；要删一章、加一章或者调章节顺序也行，
> 那种改动我会回 JSON 改完、重渲受影响的那一章。别直接改 HTML——JSON 会失同步。

## 硬约束

前四条漏了会**静默出错**——报告照样写得出来，只是在 KyDog 里打开后不对劲，而你不会收到任何报错：

1. **只用模板文末那一个 `<script>` 块，不新开 `<script>` 标签。** 查看器沙箱现在给
   `allow-scripts`，脚本能跑（方向键翻节、逐条入场、SVG 描边、目录高亮、
   抬头那条封面带都靠它）；
   新逻辑加进那一处，不要另起标签。
2. **不引任何外部资源**：CDN、Google Fonts、unpkg、`<link rel=stylesheet>`、`@import`、
   网络字体、`<img src="http…">`、CSS 里指向网络的 `url()`、脚本里的
   `fetch` / `XMLHttpRequest` / `WebSocket`——沙箱同时注入了一条严格 CSP
   （`default-src 'none'`、`connect-src 'none'`、`img-src data:`），
   **上面这些全会被拦掉，写了就是白写，而且页面上只是缺一块，不报错**。
   所以图片改用报告目录树内的相对路径 `<img src="papers/…">` 引用，查看器渲染时会
   自动读文件转成 `data:` URI 内嵌——不要自己打 base64，见 `references/figures.md`。
3. **所有外链写 `target="_blank" rel="noopener"`。** 沙箱不给 `allow-top-navigation`，普通链接点下去会试图在 iframe 里就地跳转。指向论文的 `<a href="https://…">` 是链接不是资源，允许；把它当资源加载（`img` / `link` / `@import`）不允许。
4. **颜色一律写成 `var(--ink, #2a2620)` 这种带 fallback 的形态**，变量名只能取自模板头部注释里的那份清单。写死颜色的报告在 midnight 主题下会瞎眼；用清单外的变量名则永远走 fallback，等于写死。

后面几条是操作与内容纪律：

5. **报告 HTML 与 `.learning-deck-*.json` 都只能用 `edit` 改。**
   整文件操作只有两次、只有这两次：`cp` 模板出 HTML（第 5.5 小步），
   `write` 建 JSON 骨架（第 5.1 小步）。之后两个文件都只用 `edit`。
   **`python` / `python3` / `perl` / `sed` / `awk` / `node -e` 一律不许用来改这两个文件**
   ——不管是就地正则手术，还是「把整个 `<body>` 拼成一个字符串写回去」。
   **也不许拿脚本去「只读校验」JSON**：`node` 在 Electron 里确实存在，但一旦开了
   「校验可以用脚本」的口子，上两次的教训是它会长成「修改也用脚本」。
   规则简单没有例外，才挡得住；JSON 小到读得完，用不着脚本。
   两条理由，缺一条这条纪律都挡不住：

   1. **KyDog 不保证用户装了这些运行时。** 我们只打包 fastpaper，不打包任何语言运行时；
      `python3` 在你的机器上能跑，在用户的机器上可能直接 127。这跟 `rg` 是同一类事
      （见第 8 条），只是失败得更晚——报告已经写了一半。
   2. **它绕过 `edit`。** `edit` 一次替换一处、匹配不上会**报错**；用脚本改文件是把
      整份产物交给一次字符串拼接，错了**不报错**——文件还在、还能打开，只是少了一节。
      这不是假想：v1 那次 `perl -0777 -i -pe 's/\n<div hidden aria-hidden="true">.*…/s'`
      吃掉了整段；v3 那次是 `python3 -c '…p.read_text()…body="""<body>…'`，
      **把整个 `<body>` 重写了两遍**。同一个错误换了两种语言各犯一次。

   ⚠️ 这条禁的是**改这两个文件**。`references/layout.md`「交付前自检 · HTML 层」
   H4 那个管道里的 `sed`（把 grep 的输出削成 id）是只读的，照抄就是了，
   不在这条禁令的范围内。
6. **HTML 是产物。渲染完发现不对，先分清是三样里的哪一样再动手。**

   | 不对的是 | 在哪改 |
   |---|---|
   | **内容**——一段话、一个例子、一行行内标记，以及加块 / 删块 / 换顺序 | **回 JSON 改**，再同步到 HTML |
   | 图的**意图**——这张图该讲哪一步、caption、图号 `num`、出处 `credit` | **回 JSON 改** `sketch` / `caption` / `num` / `credit`，然后把那张图**重画一遍**贴回 HTML |
   | 图的**画法**——SVG 标记本身：框排不下、线画歪了、`<defs>` 里 id 撞了、颜色 class 用错 | **就在 HTML 上改那张 `<svg>`**，JSON 不动 |

   最后一行不是破例，是**JSON 里根本没有画法这样东西**（SVG 不进 JSON，见第 5 步）。
   在 HTML 上调一张图的线条，不会让 JSON 失同步——JSON 说的是「画一条时间轴，
   轴上四个刻度」，那句话在你把线条挪正之后仍然是真的。

   前两行怎么改：

   - **改一段话 / 一行标记** —— 先在 JSON 上改那一行，再把**同一个 `oldText` /
     `newText`** 贴进 HTML。两次 `edit`，第二次是第一次的复制粘贴（JSON 里那些
     数组元素与 HTML 里的行逐字相同，连缩进都一样，见 `references/deck-json.md`）。
   - **加块 / 删块 / 换块的顺序（都在同一章之内）** —— 回 JSON 改完，把那**一章**重渲一遍。
     一章一百来行，不是整篇。
   - **删一章 / 插一章 / 换章的顺序** —— 这是另一件事，别按上一行办。重渲那一章只是
     其中一步，还要跟着改**编号**（`§N` 全篇连续）、**`id`**（`id === "c" + number`）、
     **目录条目**、**知识地图节点**、**页内锚点**、**图号**、**术语表的 `where`**。
     照 `references/layout.md`「事后改结构：删一章 / 插一章 / 换顺序」那一节一步步走，
     那里把每一处都列出来了。
   - **改图的意图** —— 没有复制粘贴的便宜可占：`sketch` 变了，图就得照新的 `sketch`
     重画。这是「SVG 不进 JSON」明码标的代价，不要为了省这一趟就只改 HTML 上的图注。

   **除了图的画法那一格，不许只改 HTML 不改 JSON。** JSON 一旦跟内容失同步，
   它就成了一份骗人的存档，下次拿它重渲会得到一份和用户手上那份不一样的报告
   ——而且不报错。（图本来就重渲不出原样，那是已知的、写在明处的代价；
   正文对不上则是纯粹的事故。）
7. **没渲染完的位置留在原地，不许「藏」。** 不要把还没填好的东西塞进 `<div hidden>`
   或 `aria-hidden="true"` 里等着回头再处理。为什么：藏起来的内容还在文件里，
   ⌘F 搜得到、导出 PDF 时可能露出来，而且你最后还得写个正则去删它——那正是第 5 条。
   一节处理不完就先不动它（那处 `⟨待填⟩` 注释原样留着，自检 H1 会把它列出来），
   处理完了再一次替换掉。
   ⚠️ 模板自己有三处 `aria-hidden="true"`（抬头的封面带 `.hero-band`、目录的小三角
   `.toc-caret`、meta 里的分隔点 `.meta-sep`），那是**纯装饰元素的正确用法**，
   要原样保留——这一条禁的是拿它藏内容。
8. **HTML 层自检固定用 `grep`。** KyDog 不打包 ripgrep，`rg` 一定返回 127，跑三次也一样。
   命令清单在 `references/layout.md` 的「交付前自检 · HTML 层」，**照抄，不要即兴发挥**。
   （系统提示词里那句「用 bash 做 ls / rg / find」已经改成 `grep` 了，见
   `src/main/agent/systemPrompt.ts`——这条纪律不再是唯一的防线，但仍然保留。）
9. **重画的图必须标「改画自 XX（年份）Fig.N」+ 外链，且不许把原图说成自画、把自画说成原图。**
   散点、热图、生存曲线这类**数据图不重画**——改成指路卡片。详见 `references/figures.md`。
10. **不建目录、不写脚本、不落中间文件**（含 `-o`）；**一个 DOI 都不许编**，每篇 `fastpaper get` 回源核验过。
    ⚠️ `.learning-deck-*.json` **不是中间文件**，是和 HTML 并排的产物，交付后留着（第 5.6 小步）。
11. **用用户说话的语言写。**

## 报告结构

三层同心圆：先给地图，再补前序，然后是主体，最后总结与附录。

```
① 抬头   ② 知识地图   ③ 前序速览
④ 知识点正文（主体，每个重点知识点一节，前面各带一屏幕封页）
⑤ 方法对比表   ⑥ 总结节   ⑦ 术语对照表   ⑧ 建议下一步   ⑨ 参考文献   ⑩ 诚实边界
```

⚠️ **v4 的 ③「速通路径」已经删掉**（用户第四次真跑后的判断：「没有任何意义」——
章节本来就按依赖顺序排、目录也把顺序摆在左边，它只是把同一串标题换个说法再列一遍）。
编号因此整体前移一位，JSON 里的 `path` 字段一并删掉。别按旧版补回来。

流程层面的三个判断：

- **④ 写哪几节由访谈定**，不由主题的「完整性」定。标「熟悉」的知识点不写正文，
  只在 ② 知识地图里作为已掌握节点出现。
- **⑤ 只在主题是「某个方法」时才有**：它与 2–3 个替代方案的假设 / 适用场景 / 代价 / 失效情形。
- **⑥ 总结节不能省。** 读者读完要有一个「合起来」的时刻，而不是读完一堆零件——
  这是这份报告和一叠讲义的区别。（v4 叫「收束」，v5 改名：那是黑话，读者看不懂。）

**①–⑩ 与 JSON 顶层字段一一对应，每个块该写成什么形状，在 `references/deck-json.md`；
每个块渲染出来的 class 与节内固定顺序，在 `references/layout.md`；
每个槽位该写成什么样，在 `references/writing.md`。**

**每个重点知识点至少一张机制图。** 讲不动到要画图的程度，说明这一节还没想清楚，
或者它本来就该并进前序速览。

## 诚实边界

⑩ 那一节不是免责声明，是读者判断这份报告能信到哪一步的依据：

- **搜不到 ≠ 没有。** 写清在哪些源、用哪些词没找到。自学报告的读者不在圈内，最没有能力自己识别缺口，所以这条在这里比在别的 skill 里更重要。
- **预印本要标明是预印本。** 未经同行评议这件事读者有权知道。
- **一个 id 都不许编。** 每个 DOI / arXiv id / PMID 都必须 `fastpaper get` 回源确认过。做不到就不写那一条。
- **每张图的来源都要交代**：哪些是原文插图、哪些是重画的（改画自哪一篇第几张）、哪些是纯自画的、哪些因为格式或体积没能取用、当前模型看不看得见图。
- **哪些论断只有摘要支撑、哪些是你的概括而非文献原话**，逐条列出来，别笼统写一句「部分内容基于摘要」。
