# 检索策略、六箱图谱、核验协议

配合 SKILL.md 第 2 步使用。前置：已经读过 fastpaper 的 SKILL.md，知道各源支持哪些 filter。

---

## 一、检索策略

### 三轴交叉

从九问的答案里抽三条轴，交叉出 query：

| 轴 | 从哪一问抽 | 例（"用可穿戴设备预测抑郁复发"） |
|---|---|---|
| 对象 / 现象 | Q1 无术语目标、Q4 受众 | depression relapse, mood episode recurrence, MDD |
| 方法 / 技术 | Q2 现状、Q3 新意 | wearable, actigraphy, passive sensing, digital phenotyping |
| 结果 / 度量 | Q9 度量标准 | prediction, early warning, PHQ-9, longitudinal |

每条轴都要带**同义词**和**上位词**。上位词很关键：领域里同一件事在不同学科有不同叫法，只搜用户用的那个词，会漏掉半个领域。

目标：**12–20 条 query，覆盖 4 个以上数据源**。把选题标题原样丢进搜索框搜一次，是这一步最常见的失败方式——它只会命中最表面的一层。

**一条命令一次调用，默认 table 格式**（见 SKILL.md「怎么跑命令」）。table 已经给了 id、标题、年份、作者，够你分诊；`--format json` 留给核验阶段比对字段用，它是 table 的 11 倍大。不要写循环、不要 `-o` 落盘、不要用脚本归并——需要归并说明你一次要太多了。

### 检索的四种角度

同一个主题至少从这四个角度各搜一轮，它们命中的是不同的论文集合：

1. **正面主题词** —— 直接搜对象 × 方法
2. **上下游** —— 搜比它更上位的问题、和更具体的子问题
3. **相邻方法** —— 同一个问题被别的方法做过没有
4. **引用链** —— 找到 1–2 篇奠基性论文后，`fastpaper cite <id> --direction incoming` 看谁引用了它。这是唯一能发现"关键词完全不同但实质相关"那批论文的办法，也是发现争议的主要入口

### 选源

按学科走，别所有 query 都打同一个源：

| 学科 | 主选 | 补充 |
|---|---|---|
| 生医 / 临床 | `pubmed` `europepmc` `pmc` | `medrxiv` `biorxiv`（预印本） |
| CS / AI | `arxiv` `dblp` `semantic` | `openalex` |
| 跨学科 / 找不准 | `openalex` `crossref` `semantic` | `core` `doaj` |
| 中文文献 | `xueshu` | 串行慢速，别并发打 |

多源之间**用 DOI 去重**。没有 DOI 的（预印本、会议论文）用标题归一化后比对，并在图谱里注明来源。

`fastpaper sources --capabilities` 是活的，拿不准某个源支不支持某个 filter 就跑一次，别猜。

## 二、六箱图谱

每篇进箱的论文都要带：标题 / 第一作者 / 年份 / 期刊或会议 / 可回源的 id（DOI、arXiv id、PMID 之一）。**没有可回源 id 的不进箱**——它没法核验，也就没法用。

空箱要保留并写"未找到"，附上你搜过的关键词和源。空箱是有信息量的，抹掉它等于抹掉证据。

### 1. 已确立的发现

多个**独立**研究结论一致的。判定标准：

- 至少 2–3 项来自不同团队的研究（同一个组的连续几篇不算独立）
- 或有一篇系统综述 / meta 分析

写法：一条结论一行，后面挂支持它的文献。别一篇论文写一条——那是文献列表不是图谱。

### 2. 争议性发现

**必须成对（或成组）列出**。单独列一篇不叫争议，那只是一篇论文。

每条争议要写清楚：

- 争的是什么（同一个问题上的两个不同答案）
- 两边各是谁、各得出了什么
- 如果能看出来：分歧的可能来源（样本人群不同 / 测量方法不同 / 统计口径不同）

争议是选题最好的落点之一——一个能解决现有争议的研究，新意和意义都是现成的。

### 3. 无发现（null results）

做了但没做出来的研究。**最难搜，最容易漏，也最有价值**——因为发表偏倚，阴性结果大量沉在水下，而不知道别人在哪里失败过，你很可能去重走同一条路。

专门的检索战术：

- **否定词组 × 主题词**：`"no significant"` `"failed to replicate"` `"null result"` `"negative result"` `"no association"` `"did not improve"`。这些词在 `pubmed` / `europepmc` / `crossref` 这类原样透传 query 的源上直接可用
- **注册报告 / 预注册**：`"registered report"` `"preregistered"` —— 这类研究承诺无论结果如何都发表，阴性结果比例远高于常规文献
- **预印本**：`biorxiv` `medrxiv` 没过期刊的发表偏倚筛子
- **翻 limitations**：第 6 箱那几篇最接近的前置论文，`fastpaper read --section discussion`，作者常在里面写"我们尝试了 X 但没能……"。这是找阴性结果最可靠的一条路
- **反向引用**：`cite --direction incoming` 找引用了某篇奠基论文却得出相反结论的

如果确实没找到：写"用 [这些词] 在 [这些源] 检索，未找到明确报告阴性结果的研究"，并提醒读者这**很可能是发表偏倚而非真的不存在**。这句提醒必须写——它是这一箱在没有内容时唯一能提供的价值。

### 4. 机制

解释"为什么会这样"的文献。和第 1 箱的区别：第 1 箱是"观察到了什么"，这一箱是"为什么"。

机制清楚的方向，风险主要在工程实现；机制不清楚的方向，风险在假设本身可能不成立。这个区分会直接进第 3 步的风险评述。

如果这一箱是空的（现象有人观察到，但没人说得清为什么），**这本身就是一个高价值的选题落点**，在第 3 步的延伸方向里点出来。

### 5. 方法论景观

大家用什么方法测这件事。每种方法记：

- 方法名 / 代表文献
- 它测的到底是什么（往往和它声称测的不完全一样）
- 已知局限（成本、样本量要求、什么条件下失效）

这一箱在第 3 步是**可行性判断的依据**——把它和 Q7/Q8 的资源答案对照，就能看出用户想做的事有没有一条他负担得起的路。

### 6. 最接近的前置论文

3–5 篇，离这个选题最近的。每篇必须配一句**精确的差距陈述**。

差距陈述的判准：**能被一句话证伪**。

| 好 | 为什么好 |
|---|---|
| "他们只在小鼠上验证过，没有人类数据" | 去查一下就知道对不对 |
| "样本量 32，检验不出 <0.4 的效应量" | 有数字，可以算 |
| "只测了急性期，没有随访超过 6 个月的" | 边界清楚 |

| 坏 | 为什么坏 |
|---|---|
| "他们做得不够深入" | 对任何论文都成立 |
| "还有进一步研究的空间" | 同上 |
| "没有考虑实际应用场景" | 除非能说出是哪个场景，否则也是万能句 |

**这一箱是整份报告价值最高的地方**。第 3 步判断"新意是否真的存在"，全靠这里的差距陈述。如果找不出任何一条精确的差距，那本身就是结论——这个选题可能已经被做了。

## 三、核验协议

一份编造出来的文献图谱比没有图谱更糟：它看起来可信，会被拿去写开题报告、拿去说服导师。所以逐条核验不是可选项。

### 3.1 存在性 + 元数据

图谱里每一篇：

```bash
fastpaper get <DOI|arXiv_ID|PMID>
```

比对四项：**标题、年份、第一作者、期刊/会议**。

| 结果 | 处置 |
|---|---|
| 查不到 | 从图谱删除，台账记"未能回源，已剔除" |
| 查到，四项一致 | 保留，台账记"一致" |
| 查到，某项对不上 | **以回源结果为准**修正图谱，台账记"已修正：<哪一项>" |
| 查到，但内容和你以为的完全是另一篇 | 删除，台账记"id 与内容不符，已剔除" |

最后一类是幻觉最典型的形态：id 是真的（属于另一篇论文），标题是编的。所以**必须比对标题**，只确认 id 能解析是不够的。

### 3.2 论断

图谱里每一条被当作事实写下的结论——数字、效应量、结论方向、"某某发现了某某"——都要能指到具体论文的具体位置。

```bash
fastpaper download <id> -d papers/
fastpaper read papers/<id>.pdf --section results --max-length 4000
```

**只读需要的段落。** `--section` 可选 abstract / introduction / methods / results / discussion / conclusion / references / full。定段读是整个核验能串行做完的前提——把二十篇全文读进上下文，后面就没有余量做判断了。

按论断的类型选段：

| 论断类型 | 读哪段 |
|---|---|
| 具体数字、效应量 | `results` |
| 结论方向、作者自己的定性 | `abstract` 或 `conclusion` |
| 样本量、人群、测量方式 | `methods` |
| 作者承认的局限、失败的尝试 | `discussion` |

拿不准这篇 PDF 有哪些节，先 `fastpaper read <pdf> --list-sections` 列一下，比猜一个再失败便宜。

要在全文里找某个说法（「作者承认了什么局限」「某个数字出现在什么上下文」），用 `--grep`：`fastpaper read <pdf> --grep "limitation" --context 500 --max-matches 10`（正则、默认大小写不敏感）。**别把全文倒出来自己翻，更不要写进文件再用脚本搜。**

| 情况 | 处置 |
|---|---|
| 原文支持 | 保留，台账记"全文核验" |
| 拿不到全文，摘要支持 | 保留，图谱里该条标 `[仅摘要]`，台账记"仅摘要" |
| 全文和摘要都拿不到 | 只保留元数据层面的引用，**不写具体数字或结论**，台账记"未获取" |
| 原文和你写的不一致 | 改成原文说的，台账记"已修正：<改了什么>" |

### 3.3 核验台账

进报告，一篇一行：

| id | 回源 | 元数据 | 论断依据 | 处置 |
|---|---|---|---|---|
| 10.1038/xxx | ✓ | 一致 | 全文（results） | 保留 |
| arXiv:2401.xxxxx | ✓ | 年份已修正 2023→2024 | 仅摘要 | 保留，效应量已删 |
| 10.1016/yyy | ✗ 查不到 | — | — | 已剔除 |

**被剔除的必须留行。** 台账的全部价值在于让人能看出你确实逐条查了、查出了什么问题。只列核验通过的那些，它就退化成了装饰。

如果整轮核验一条问题都没查出来，在台账下面写一句说明——这要么说明检索质量很高，要么说明核验做得不认真，读者有权知道你倾向于哪一种。

### 3.4 下载

进了图谱的论文都试着下到 `papers/`。失败很常见（付费墙、源不支持 download、id 类型不对、当年新发表聚合源未收录）。**先看退出码**：`4` = 这个源就是没有，换个源才有意义；`2` = 命令写错了；`1` = 别的问题。失败就在台账里记"未获取"。

**不要编造下载成功。** 用户会去 `papers/` 里找文件，找不到的那一刻，整份报告的可信度就没了。
