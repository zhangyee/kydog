# 研究选题评估

三步：**问清楚 → 查透 → 下判断**。三步是一条链，前一步的产物是后一步的输入；跳过第一步直接去查文献，你只会搜到一堆和用户真正想做的事沾边但不对焦的论文。

产物是项目根目录下的一份 Markdown 报告，加上 `papers/` 里的 PDF。

## 开工前

1. `date +%F` —— 报告文件名要用，你自己猜不准今天几号。
2. **read fastpaper 的 SKILL.md**（它在 `<available_skills>` 里）。它的检索语法各源不同、filter 支持各源不同，凭记忆猜 flag 会静默拿到错结果。不用 `which fastpaper` 确认它在——KyDog 打包分发并注入了 PATH，它一定在；真不在的话第一条检索命令的报错比探测更准。
3. 如果 `<available_skills>` 里还有别的文献检索工具（比如 slowpaper），一并用上，并在报告里分别注明哪些结论来自哪个源。目前通常只有 fastpaper。
4. 如果用户只丢了一句话（`/research-ideation` 后面没内容，或只有五六个字），先用普通对话问清楚他想做什么、在什么学科、处在什么阶段（还没开题 / 已有初步想法 / 已经在做了）。**这一步别用 ask_user_question** —— 这是开放题，做成选择题只会限制他。

## 怎么跑检索命令

AGENTS.md 的「用工具的方式」在这里全部适用：一次 bash 一条 fastpaper 命令，直接读 stdout，不建目录、不落中间文件（包括 `fastpaper search -o`）、不写脚本归并结果。

具体到这个 skill：**只有两样东西该写进磁盘**——`papers/` 里的 PDF（`fastpaper download -d papers/` 自己会建目录），和最终那份报告。

检索结果尤其不该落盘，理由不是嫌乱：**它的持久层已经存在了，就是那些数据库。** DOI / PMID / arXiv id 是稳定指针，`fastpaper get <id>` 任何时候都能把权威版本取回来。本地那份 JSON 副本从写下的那一刻起就开始过时，而核验环节本来就要逐条回源——既然无论如何都要 `get` 一遍，那份缓存从头到尾没被真正依赖过。判断要基于回源拿到的事实，不是基于磁盘上的旧拷贝。

### 选输出格式

| 场景 | 格式 | `-n 8` 的量 |
|---|---|---|
| 分诊：扫标题决定哪些值得细看 | **默认 table**（不加 `--format`） | ~1.8k 字符，带 id、标题、年份、作者 |
| 精确比对字段（核验元数据） | `--format json` | ~20k 字符，**11 倍** |

fastpaper 的 SKILL.md 让你每次都用 json，那条是给需要精确解析字段、区分 `null`（未知）和缺失的场景的。**你在分诊阶段不需要那个精度**——table 已经给了 id 和标题，看中哪篇再 `fastpaper get <id>` 拿全字段。整轮检索都开 json 是这个 skill 最容易把上下文烧光的地方。

## 第 1 步：Heilmeier 九问

George Heilmeier 1970 年代主持 DARPA 时，要求每个申请经费的人回答一组问题。这组问题至今仍是科技界评估研究项目的标准清单。九问的全文、每问在检验什么、好答案与坏答案长什么样，在 `references/heilmeier.md` —— **动手起草选项前先读它**。

### 先侦察，再起草

起草选项之前，先做一轮**侦察性检索**，只为了知道这个领域现在长什么样、主流做法叫什么、最近三年在争什么。

**规模：2 个源 × 2–3 条 query，`-n 8`，默认 table 格式，一条一条跑。** 总共 4–6 次调用，读的就是标题和年份。侦察不是普查——它只需要让你的选项贴地，多搜没有额外价值，只会把上下文烧在还没开始问问题的阶段。

告诉用户你在做什么（"我先扫一眼这个领域，然后开始问你九个问题"），别让界面静默几十秒。

侦察结果**不进图谱**，它唯一的用途是让你起草的选项贴地。这一步很值——「现在这件事是怎么做的」如果靠你的记忆答，在冷门方向上就是幻觉的起点；靠刚搜到的真论文答，选项立刻有了重量。

### 怎么问

`ask_user_question` 是选择题工具，Heilmeier 九问是开放题。桥接方式是**你先替用户起草答案，他挑一个或改写**：

- 每题给 **2–4 个候选答案**，是针对**他这个具体选题**的不同表述/不同立场，不是「有 / 没有 / 不确定」这种通用模板。模板选项对具体课题的信息量近乎为零，用户看了也不知道该选哪个。
- 最贴近你判断的那个标 `recommended`（每题至多一个）。
- 用户可以在选项之外**自己写**（工具带自由输入框）。第一轮开始前告诉他这件事，否则他会以为只能三选一。

工具约束（违反会整批被拒）：

- **必须单独调用**，不能和别的工具放在同一批 tool call 里。
- 一次 1–4 题，每题 2–4 个选项。
- `header` 不超过 12 个字符。

九问分三轮，每轮 3 题：

| 轮 | 题 | header 建议 |
|---|---|---|
| 1 | Q1 无术语目标 · Q2 现状与局限 · Q3 新意与胜算 | 目标 / 现状 / 新意 |
| 2 | Q4 谁在乎 · Q5 成功后的改变 · Q6 风险 | 受众 / 影响 / 风险 |
| 3 | Q7 资源 · Q8 时间 · Q9 成功的度量 | 资源 / 周期 / 度量 |

三轮之间可以根据上一轮的回答调整下一轮的选项——用户在 Q1 里选的表述会改变 Q4「谁在乎」的合理候选。别把三轮的选项一次性想好然后照本宣科。

### 处理回答

- **用户跳过某题**（回来的文本是「用户跳过了这一题」）：那题就是未作答，报告里如实写。**跳过本身是信息**——尤其是 Q9 跳过了，说明这个选题还没有成功标准，这件事必须进第 3 步的评述。别替他补一个。
- **用户关闭了提问**：这一轮就停，问他是想换个方式聊还是先搁置。不要自说自话把九问替他答完。
- **Q1 是最难也最有名的一条**。如果用户最终选定的答案里还有本领域的黑话，如实指出来（"这句话里的 X 和 Y，外行听不懂"），并给一个更白的改写供他确认。Heilmeier 的原话是：说不明白，说明还没想清楚。这是这一步最有价值的产出，别为了显得顺滑而放过。

九问收齐后直接进第 2 步，不必再让用户确认一遍——他刚刚一题一题选过了。

**九个问题不进报告，正文和附录都不进。** 报告第一章是把九个答案综合成的散文，那才是产物；原始问答是**原料**，读者拿到综合就不需要它，而回答问题的人更不需要看自己刚填过的东西。真要追溯，会话记录里存着完整原文。

还有一个具体理由：`ask_user_question` 的结果只回给你选项的 `label`（1–5 个词的短标签），不回 `description`。照抄回来就是一列六字词组（「兼顾预测识别」「院外监测空白」），脱离上下文谁都看不懂。**写第一章时要用你自己起草那个选项的完整含义 + 用户的自定义补充，不是那个短标签。**

## 第 2 步：文献图谱与核验

详细的检索策略、六箱的判定标准、核验协议在 `references/literature-map.md` —— **开始检索前读它**。这里只给骨架。

### 2.1 检索

从九问的答案里抽出三条轴：**对象/现象词**、**方法/技术词**、**结果/度量词**。三轴交叉出 query，每轴都要带同义词和上位词。目标是 12–20 条 query 覆盖 4 个以上数据源，不是把选题标题原样丢进搜索框搜一次。

**跑法：一条一条跑，默认 table 格式分诊，看中的再 `fastpaper get <id>` 拿全字段。** 不要为了"一次搜完"去写循环或落盘——12–20 条 table 输出（每条约 1.8k 字符）是你读得下的量，而同样条数的 json 不是。

按学科选源（fastpaper 的 `sources --capabilities` 是活的，拿不准就跑一次）。多个源之间去重靠 DOI。

**边搜边记数**：每个源跑了几条检索式、命中多少、去重后剩多少、筛出多少送进核验。报告开头第一行就是这个漏斗，**九个数各不相同**：

> 源数 N1 → 检索式数 N2 → 命中 N3 → 去重后 N4 → **筛出进核验 N5** → 进入结论 N6；
> 全文 = **本轮新下 D1**（§2.4 两次 `ls papers/` 取差）+ **`papers/` 原有 D3** = N8

N4 → N5 那一档是分诊，不写读者会以为你把文献扔了。

**D1 和 D3 必须分开写。** 只报一个「取得全文 N8 篇」，读者一定读成「这 N8 篇都是本轮下下来的」——当大部分全文来自 `papers/` 原有时，这个误读和事实正好相反。这是整行最容易骗到人的地方。

这个漏斗决定读者怎么掂量后面所有结论的分量。**事后补不出来，当场记。**

### 2.2 六箱图谱

把检索结果归到六个箱子。空箱子也要留着并写明"未找到"——空箱子是有信息量的：

1. **已确立的发现** —— 多个独立研究结论一致
2. **争议性发现** —— 结论互相矛盾的，必须**成对列出**，单独列一篇不叫争议
3. **无发现（null results）** —— 做了但没做出来的。最难搜、最容易漏，`references/literature-map.md` 里有专门的检索战术
4. **机制** —— 解释"为什么会这样"的文献
5. **方法论景观** —— 大家用什么方法测这件事，每种方法的已知局限
6. **最接近的前置论文** —— 离这个选题最近的 3–5 篇，每篇配一句**精确的差距陈述**

第 6 箱是整份报告价值最高的地方。差距陈述必须**能被一句话证伪**：

- 好："他们只在小鼠上验证过，没有人类数据" —— 可以查证，对错分明
- 好："他们的样本量是 32，检验不出小于 0.4 的效应量"
- 废话："他们做得不够深入"、"还有进一步研究的空间" —— 这种句子对任何论文都成立，等于没说

**"六箱"是你的工作说法，不是报告的目录。** 报告里这一章叫「文献图谱」，六个小节直接用上面那六个名字：已确立的发现 / 争议性发现 / 否定结论的发现 / 机制 / 方法论景观 / 最接近的相关研究。**但正文里一次都不要出现"第 N 箱"**——读者不知道你分了几个箱，也不需要知道。同理："三轴取词""核验台账"这些词只属于你的工作过程，不进交付物。

### 2.3 核验（两级，逐条做）

图谱里的每一篇、每一条论断，都要能指回真实来源。这一步是这个 skill 存在的理由——一份编造出来的文献图谱比没有图谱更糟，因为它看起来可信。

**存在性 + 元数据**：每篇 `fastpaper get <id>`，比对标题、年份、第一作者、期刊是否与你写进图谱的一致。

- 查不到 → 从图谱里删掉
- 查到但和你写的对不上 → 以回源结果为准修正，或删掉
- **两个源自己打架**（比如 OpenAlex 记 2023、Europe PMC 记 2024）→ 并列呈现并说明，不要擅自挑一个。这是 AGENTS.md 核验纪律的原话，也是唯一诚实的处理

**论断**：图谱里每一条被当作事实写下的结论（数字、效应量、结论方向），必须能指到具体论文的具体位置。

- `fastpaper download <id> -d papers/` 拿 PDF，再 `fastpaper read papers/<id>.pdf --section results --max-length 4000` 定段回原文比对
- **只读需要的段落**，不要整篇读进来。定段读是这一步能串行做完的前提
- 拿不到全文的，退回摘要；只有摘要支持的论断在报告里标 `[仅摘要]`
- 原文对不上你写的 → 改成原文说的，或删掉这条论断

**边核边记两组数**，报告的「文献核验结论」一节要用，事后数不出来：

- 篇的层面：核验了多少篇、多少篇进结论、多少篇剔除（各因为什么）、几处元数据被修正
- 论断的层面：**核对了多少条结论**、其中多少条经全文比对、多少条仅摘要支撑、多少条因与原文不符被修正或删除

**逐篇的核验记录进报告附录 A**，一篇一行：文献 / 回源结果 / 元数据一致 / 论断依据（全文 / 仅摘要 / 未获取）/ 处置。被剔除的也要留行——只列核验通过的，这张表就成了装饰。

**正文里放的是结论，不是流水表**：「文献图谱」那一章末尾一节叫「文献核验结论」，用上面两组数字回答"这些结论核到什么程度"。它决定读者拿这份图谱当什么用，所以排在述评之前。

### 2.4 下载

**开工时 `ls papers/` 一次，写报告前再 `ls papers/` 一次。** 这两次不是重复：

- 第一次决定要下哪些。这个目录可能已经躺着用户自己放的、或前几次会话下的论文——本轮要的说不定就在里面，直接 `fastpaper read` 即可，连 `download` 都不用调。
- 第二次是为了**数准**：两次的差就是本轮新增的 D1，第一次里与本轮选题相关的就是 D3。**别凭记忆数自己发过几条 download 命令**——换过源、先失败后成功的，记忆一定算错。两个 `ls` 是协议层事实，记忆不是。

比对靠文件名，规则是：**DOI 的 `/` 换成 `_`**（`10.2196/31129` → `papers/10.2196_31129.pdf`），arXiv id 和 PMC id 原样（`1706.03762.pdf`、`PMC10944676.pdf`）。目录里也会有用户手工命名的文件（`Azadian_NatBiotech_2026.pdf` 这种），按标题认。

剩下的用 `fastpaper download <id> -d papers/`。重复下载它自己会挡（`File already exists: ...`，退出码 0），所以先 `ls` 是为了少调用和捡现成的，不是为了防覆盖。

很多下载会失败（付费墙、反爬虫、返回落地页、无开放获取、源端限流，以及当年新发表、聚合源尚未收录）。**先看退出码**：`4` = 请求没问题、这个源就是没有，换个源才有意义；`2` = 命令写错了；`1` = 别的问题。`4` 之外照 fastpaper 错误里给的判断办，别自己另起一套重试策略。失败就在附录的核验表里记「未获取」。**不要编造下载成功**——用户会去 `papers/` 里找文件。

**中途改口要回头改数。** 典型的错法：先跟用户说「这 9 篇都没下下来」，之后换源又试了 2 次、成了 1 次，报告里却还写着旧数字，连"9 = 1 + 8"这种自相矛盾的句子都留下来了。任何在会话中途说出口的计数，写报告时都要按最后一次 `ls papers/` 重新核一遍。

## 第 3 步：述评与其他方向

### 述评

**述评是「述」和「评」两个动作，缺一不可**：先把文献在某个问题上说了什么叙述清楚，再评它对这个选题意味着什么。只述不评是综述，只评不述是空谈。这是这一章唯一的形式要求，也是最容易做丢的一条。

**写成散文，不要写成打分表。** 判断的分量来自论证过程，不来自表格里的标签——一张全是「部分支持」的表，读者看不出你凭什么这么判，也就没法不同意你。

**立场在开头和结尾各说一次**，中间全是论证。这是述评的规矩，不是排版偏好：读者需要先知道你站哪，才能带着立场去读你的论证。

主体按四个次级主题展开，每一节都是「述 → 评」两段：

| 次级主题 | 述什么 | 评什么 |
|---|---|---|
| 新意还在不在 | 最接近的相关研究做到了哪一步 | 他声称的新意是真空白，还是已被填掉；剩下的够不够撑一个课题 |
| 做得成做不成 | 现有方法各自要付出什么代价、谁在哪一步栽过 | 他手上的资源和周期，买不买得到他要的那一步 |
| 风险在不在他以为的地方 | 争议性发现与否定结论的发现指向哪些失败模式 | 和他在 Q6 说的是不是同一批；有没有他没提但文献反复出现的 |
| 声称的价值成不成立 | 已确立的发现支持到什么程度 | 他说的受益和改变，证据支持到哪一步，从哪一步开始是外推 |

**把判断的标准写出来。** 评价不能是"我觉得"——写明你按什么判的（差距陈述是否可证伪、所需方法是否在他资源内可及、成功标准是否可观测）。标准写出来，读者才能不同意你；不写，这份述评就只是一个意见。

**不要另附"九问逐条落点"那种表。** 四节散文已经把他声称的每一条都对过一遍了，再来一张表是把刚讲完的话再列一遍。他答过的问题不需要在报告里被逐条复述和打分。

有一种情况必须在散文里点出来：**某一问被跳过了**。尤其 Q9——一个说不出成功标准的选题，三年后没人（包括他自己）能判断做成没有，这件事要写进"做得成做不成"那一节。

**判断三档取其一**：

- **值得做** —— 差距真实、方法可及、资源匹配
- **需要收窄后再做** —— 方向对但太大或太散，说清收到哪里、为什么砍掉的那部分撑不住
- **建议换方向** —— 差距不存在、或已被填、或资源根本不够

引用**指到具体研究（作者+年份），不要指报告的章节编号**。和稀泥（"有一定价值也有一定挑战"）对用户没有任何用——他找你就是要一个判断。判断为负也直说，这比让他花三年撞墙仁慈得多。

判断是"需要收窄"时，在结尾重申判断之后给：收窄后的选题陈述、为什么这样收、以及 3–6 条**开工前要先定的事**。每一条都要对应文献里一个具体的失败模式（谁在哪一步栽了），不是通用的研究建议。

### 其他值得做的方向

3–5 个，同主题下的。**用综述的写法**：先叙述文献里的具体张力或空白，带作者年份的引用，再从中引出选题。

好的写法：

> González-Cabeza 等（2025）报告三导联在静态五分类上 micro-F1 达 77%、接近 12 导联的 78%，而 Zepeda-Echavarria 等（2024）在真实四电极设备上对 OMI 的敏感度只有 65%。这一落差目前没有研究归因过——究竟来自导联选择，还是来自真实采集条件？据此可以……

坏的写法：

> 挂在：第 2 箱"三导联是否足够"的争议。

内部编号读者看不懂，也不该看懂。你自己心里知道每个方向挂在图谱的哪条空白上——挂不上就是凭想象编的，删掉——但**写出来的必须是文献本身**。

也不要写"可以研究 X 在 Y 领域的应用"这种任何领域都能套的句子。

### 报告

模板在 `assets/report-template.md`，用 `write` 写到**项目根目录**：

```
research-ideation-<主题简称>-YYYY-MM-DD.md
```

主题简称用短横线连接的英文或拼音，别用空格。日期用开工时 `date +%F` 的结果。

**只用纯 Markdown，不要写 HTML 标签。** KyDog 的渲染器是 ReactMarkdown + remark-gfm，没有 rehype-raw——`<details>`、`<summary>`、`<br>` 会原样显示成字符串。要折叠内容就放附录，没有折叠这个选项。

两件容易写砸的事：

- **开头第一行是漏斗数字**（见 §2.1 的九个数），不是"检索工具：fastpaper"。用什么工具是内部实现，读者不关心；证据有多厚才决定他怎么读后面每一句。写完核一遍 N3 ≥ N4 ≥ N5 ≥ N6、N8 = D1 + D3、N8 ≤ N5——对不上就是记错了。
- **第一章是散文，不是问答**。用三到五段把这个选题讲清楚。读者可能只读第一章和述评那一章，这两章各自都要能单独读懂。

写完在对话里给出摘要：判断是哪一档、最关键的两三条依据、报告路径、`papers/` 里下到了几篇。别把整份报告复述一遍——它已经在文件里了。

## 诚实边界

这几条不是客套，是这份报告能不能被人拿去用的前提：

- **搜不到 ≠ 不存在**。要说「在这些源、用这些关键词，没有找到」，把源和关键词列出来。让读者能判断是真空白还是你没搜到。
- **fastpaper 拿不到的就说拿不到**。它没有影响因子，引用关系只有 semantic 和 openalex 两个源有；其余任何"相关性"（共同作者、同一期刊、概念相近）都是 proxy，用了就要标明是 proxy。
- **一个 id 都不许编**。整份报告里出现的每个 DOI / arXiv id / PMID，都必须是 `fastpaper get` 回源确认过的。做不到就不写那一条。
