# 前沿简报

产物是**一份 1500–2500 字的 Markdown 简报**，读者是这个方向的内行。

**不讲背景，不建共识地图，不复述这个方向是什么。** 那是 `/literature-review` 的活。这份只回答一个问题：**这一年里，我可能错过了什么。**

**用用户说话的语言写。**

## 和另外两个 skill 的分工

| | 问题 | 时间取向 | 读者 |
|---|---|---|---|
| `/research-ideation` | 我这个选题站不站得住 | 验证一个假设 | 选题人 |
| `/literature-review` | 这个方向是什么 | 向后看，共识已沉淀 | 写论文的人 |
| **`/research-frontier`** | **最近发生了什么，我该盯什么** | **向前看，共识尚未形成** | **已在圈内的人** |

## 开工前

1. `date +%F` —— 时间窗和文件名都要用。
2. **read fastpaper 的 SKILL.md**（在 `<available_skills>` 里）。各源语法和 filter 支持不同，猜 flag 会静默拿到错结果。
3. `ls papers/` —— 可能已有现成的论文。
4. **确认方向够具体**。"人工智能在医学中的应用"这种粒度做不出前沿——一年里什么都在发生，说了等于没说。太宽就用普通对话请用户收窄到一个能被一句话描述的方向。

## 怎么跑检索命令

AGENTS.md 的「用工具的方式」全部适用：一次 bash 一条 fastpaper 命令，直接读 stdout，不建目录、不落中间文件（含 `-o`）、不写脚本归并。多条检索式用多个并行调用。

**但下载和可能被限流的调用别一次发太多**——实测一次并行 15 个 `get` 会让 Crossref 返回 429，一次并行 10 个 `download` 会在学到教训前全部失败。这类操作分成 4–6 个一批。

只有两样东西该写进磁盘：`papers/` 里的 PDF，和最终那份简报。

**输出格式**：扫标题用默认 table（`-n 8` 约 1.8k 字符）；只有要精确比对字段时才 `--format json`（同样条数 ~20k，11 倍）。

## 第 1 步：检索

**时间窗默认最近 12 个月**（`--after <今年减1>-<当前月>-01`）。内行已经有两年的图，简报要给的是他这一年可能错过的。这个方向节奏慢、12 个月搜不出东西，就放宽到 18 或 24 个月，**并在简报里写明放宽到了哪**——一个一年没有新东西的方向，本身就是结论。

五条入口并行跑，**它们互不依赖**：

```bash
# 1. 主题词，近 12 个月
fastpaper search pubmed "<主题词>" --after <今年减1>-<月>-01 -n 10

# 2. 预印本——领先期刊 6–18 个月，前沿的第一现场
fastpaper search arxiv   "<主题>" --after <今年减1>-<月>-01 -n 8
fastpaper search biorxiv "<主题>" -n 8
fastpaper search medrxiv "<主题>" -n 8

# 3. 跨学科源——本学科的检索永远看不到他们
fastpaper search arxiv "<主题>" --field <相邻学科类目> --after <今年减1>-<月>-01 -n 8

# 4. 近期发表却已积累引用 = 升温（只在 semantic 上排序）
fastpaper search semantic "<主题>" --after <今年减1>-01-01 --sort citations -n 10

# 5. 谁在跟进最近的关键工作
fastpaper cite <近期某篇的DOI> --direction incoming -n 20
```

第 3 条的跨学科入口很关键：从别的领域带方法进来的人，引的是**他们那边**的正典，用本学科的词和引用网都找不到。生医方向去 `arxiv --field eess.SP / cs.LG`，CS 方向去 `pubmed` `europepmc`。

### 三个必须避开的坑（都实测过）

**不要算"引用增速"。** `cite` 没有 `--sort` 也没有日期过滤，只能截断；实测同一篇论文（总引用 280），近一年引用占比在 `-n 25 / 60 / 120` 下分别是 28% / 43% / 56%——**分布随 `-n` 漂移**，算出来的是你填的参数不是热度。要说升温就用上面第 4 条，并如实叫它"近 N 年发表且引用数居前的工作"。

**`--sort citations` 在这份 skill 里只有一个合法位置：`semantic`。别的源一个都不许用，没有例外。** 不许的理由分两类，两类都不是「试一下看看」能解决的：

- **会直接报错的**：这些源不提供引用数，命令失败，白花一次调用。
- **不报错但结果是错的**：按引用排序时相关性权重被压过，返回的是整个学科的巨无霸（搜可穿戴心电返回 UK Biobank、ESC 指南）。这类更贵——它看起来成功了。

要按引用排序而 `semantic` 不合适（比如它对这个主题召回太差），**就不排序**：换 `--sort date` 或干脆不排，在附录里写明本轮没做引用排序。不要去别的源上试。

**`CITED:>N` 不生效，要用区间形式 `CITED:[N TO *]`。** 实测 `>` 形式被源端静默忽略、不报错（阈值 500 和 100000 返回完全相同的结果）；换成 Lucene 区间形式才真的过滤：

```
CRISPR AND CITED:[0 TO *]      → 20 条
CRISPR AND CITED:[10000 TO *]  →  5 条
CRISPR AND CITED:[50000 TO *]  →  1 条
```

推而广之：**任何写进 query 字符串的过滤条件，用一个极端值再跑一次验证它真的生效**（阈值拉到极高应该返回零条）。这类条件由源端解析，fastpaper 的校验层看不到，写错不会报错。两次调用换掉一整类静默错误。

**没有的东西**：下载量（18 个源都不提供）、发文量逐年趋势（`search` 不返回总命中数）、临床试验注册库（ClinicalTrials.gov 不在源里）。不要用别的指标冒充，也不要写"广受关注"这种含糊话。

## 第 2 步：五个信号

简报的骨架就是这五节。**引用数天然滞后 1–2 年，用它测前沿本来就晚一拍**——所以后四条都不依赖引用。

### 1. 近期重要进展

按**新在哪**分组，不按时间流水。三类分开：**新方法 / 新数据或新场景 / 新结果**。预印本必须标明。

判准：一个内行看了会说"这个我没注意到"，而不是"这个我知道"。做不到就说明检索太浅，换词再来。

### 2. 既有结论的修正

**这一节对内行最值钱**——他脑子里已经有一张图，最想知道的是**哪里需要改**。

写法是成对的：**原来大家认为 X（挂旧文献）→ 新工作显示 Y（挂新文献）→ 动摇程度**。动摇程度分三档：**被推翻 / 被限缩了适用范围 / 出现了第一个反例**。三档含义完全不同，别含糊成"受到挑战"。

这一节空着也要保留，写"未发现"——一年里没有任何假设被动摇，说明这个方向在收敛而不是在开拓，这是个结论。

### 3. 主要研究团队及其研究脉络

两类都要，**持续深耕的放前面**。

#### 3a. 持续深耕的团队

一个连续多年产出、成果成体系的团队，他们的**演进轨迹**比任何单篇新论文都能说明方向要往哪走。这是内行最想知道又最难自己看出来的——单篇论文他都看过，但把一个组五年的工作连成一条线，需要专门去拉。

做法：从检索结果里挑反复出现的作者，逐个拉他们的连续产出。

```bash
fastpaper search pubmed "<主题>" --author "<姓 名首字母>" --sort date -n 10
```

`--author` 在 `pubmed` `pmc` `europepmc` `crossref` `openalex` `arxiv` `core` `openaire` `doaj` `zenodo` `hal` 上可用；`semantic` `dblp` `scholar` `xueshu` `biorxiv` `medrxiv` 不支持，但会明确报错（`Error: semantic does not support --author`），不会静默失败——那几个源把人名写进 query 字符串。

**要写的是轨迹，不是论文列表。** 挑 2–4 个节点，让人看出他们从什么做到什么：

> Al-Zaiti 组（Pittsburgh）：2023 年做可解释性与房颤预测 → 2024 年参与心脏病 AI 的科学声明（进入指南层）→ 2025 年转向 saliency map 的临床可用性、疑似 ACS 风险分层、OMI 专用网络 → 2026 年做对抗去偏与时序补全。**从"能不能做"走到"能不能信、公不公平、缺数据怎么办"**——这条线说明这个方向的主战场正在从模型性能转向临床可信度。

每个团队写：**谁 / 在这个方向持续了几年 / 轨迹的 2–4 个节点 / 最近一年指向哪 / 凭什么算引领者**。最后一条要有依据——被引用链反复指向、定义了某个任务或基准、写进了指南或共识声明，都算；"发得多"不算。

#### 3b. 新进入该方向的团队

尤其是**跨学科迁入的**。一个做信号处理的组突然开始做临床终点，值得盯。

每个写：谁、从哪个领域来、带了什么方法、为什么这次迁入可能成立。

### 4. 新出现的术语

这个方向最近长出来的词。**每个新术语后面要跟一句「用它能搜到什么老词搜不到的」**——这是简报里唯一能直接改善读者自己检索能力的部分，比列几篇论文有用得多。

术语从哪来：读新论文时留意那些**在一年前的文献里不出现**的词。

### 5. 未决争议

活跃的分歧点。**成对写**：谁得出了什么、对面是谁、分歧可能来自哪里。

前沿的定义性特征是**还没有共识**。一个方向如果所有人结论一致，那它已经不是前沿了，是共识——这本身值得在简报里点出来。

## 第 3 步：核验

**产物短不等于核验可以松。** 一份编造出来的前沿简报会直接影响别人的投入决策。

**存在性 + 元数据**：每篇 `fastpaper get <id>`，比对标题、年份、第一作者。查不到就删掉；两个源打架就并列呈现，不擅自挑一个。

**论断**：简报里的每个具体数字、效应量、结论方向都要能指到原文。`fastpaper read papers/<file>.pdf --section results --max-length 4000` 定段回原文。

**拿不准这篇 PDF 有哪些节，先列一下**，比猜一个再失败便宜：

```bash
fastpaper read papers/<file>.pdf --list-sections
```

Nature 系期刊（Scientific Reports、Nature Communications）的 PDF **没有 `Abstract` 和 `Introduction` 标签**，体例是 **摘要 → Results → Discussion → Methods**，不是 IMRaD。对这类 `--section abstract` 会干净报错——先 `--list-sections` 就能避开。

**要在全文里找某个说法，用 `--grep`，不要把全文倒出来自己翻**：

```bash
fastpaper read papers/<file>.pdf --grep "limitation" --context 500 --max-matches 10
```

正则、默认大小写不敏感（要区分大小写用 `(?-i)`）。核对「作者承认了什么局限」「某个数字出现在什么上下文里」这类问题，它比读整节快得多也省得多。

拿不到全文的退回摘要，**在附录里标明哪些论断只有摘要支撑**。

**「只有摘要」要分成两种写，不许合并。** 附录的文献清单里，核验层级三选一：

| 标签 | 含义 |
|---|---|
| `全文` | 读过全文——本轮下载的，或 `papers/` 里原有的 |
| `未取全文` | 源上拿得到，本轮判断摘要够用、没去取 |
| `源无全文` | 试过了，源上就是没有 |

后两个都只有摘要支撑，但读者的反应完全不同：「未取全文」是他自己能去拿，「源无全文」是他去了也拿不到。混成一句「仅摘要」等于把前者说成了后者——**读者会以为你试过而拿不到，其实你没试**。判成 `未取全文` 不丢人，附录里写清"为什么判断摘要够用"就行；判错标签才是问题。

## 第 4 步：下载

开工时 `ls papers/` 一次，写简报前再 `ls` 一次，两次取差就是本轮新增。别凭记忆数发过几条 download 命令。

文件名规则：DOI 的 `/` 换成 `_`，arXiv id 和 PMC id 原样。

**这个 skill 的全文获取率天然低，这是结构性的，别浪费调用去救。** 实测一轮 9 次下载 6 次失败，失败的**全是当年发表的论文**——PMC / Europe PMC / CORE 的全文入库有几周到几个月延迟，而前沿简报按定义搜最近 12 个月，越靠近今天越拿不到。

**换源基本救不回来**：那 6 篇逐个试过 `europepmc` 和 `core`，零成功；题名去 `arxiv` 找预印本，五篇全无命中（临床行为医学的预印本在 medRxiv，而 medRxiv 自己封了 PDF 下载）。`unpaywall` 也不行——它对这些论文只有落地页没有 PDF 直链。所以：

- **先看退出码。** `4` = 请求没问题、这个源就是没有（没这篇 / 没 OA 副本 / `--grep` 无命中），换个源或换个 id 才有意义；`2` = 命令写错了，改命令；`1` = 别的问题。**不要看到失败就一律重试**——退出码已经告诉你该不该。
- **`4` 之外，照 fastpaper 给的判断办。** 它的下载错误会告诉你试的是哪个 URL、以及值不值得换源（例如「Other resolvers usually hand back this same URL, so opening it yourself is more likely to help than retrying through another source」）。**照抄它的判断，别自己另起一套重试策略。**
- 报告失败原因时**写成因，不要只抄错误串**：「2026 年新发表，聚合源尚未收录全文」比「Response is not a PDF」对读者有用得多
- **开放获取 ≠ 拿得到**。Frontiers 这类完全 OA 期刊的新论文，官网免费但聚合源里没有

因此这份简报**大量论断只有摘要支撑是正常的**，附录里如实标注即可，不必因为全文少而心虚——但也不能因此把摘要里的话当全文核验过。

**上面这段说的是期刊论文。** 它是在 PMC / Europe PMC / CORE 的入库延迟上学到的，对预印本源不成立——`arxiv` `biorxiv` `zenodo` `hal` 的 download 都是 ✓，新论文当天就有 PDF。所以：没下载的预印本，附录里的标签是 `未取全文`，不是 `源无全文`，理由也要写成"判断摘要够用"，不能借用"结构性拿不到"那套说辞。

**不要编造下载成功。**

## 第 5 步：写简报

模板在 `assets/briefing-template.md`，用 `write` 写到**项目根目录**：

```
research-frontier-<方向简称>-YYYY-MM-DD.md
```

和 `research-ideation-*`、`literature-review-*` 同一套样式。

**结论先行。** 开头 3–5 条一句话结论，每条挂文献。读者可能只读这一段——它要能独立成立。

**默认读者是内行**：不解释这个方向是什么、不定义术语（除了第 4 节那些新的）、不铺垫为什么重要。省下的篇幅全给判断。

**每条判断要能指到具体文献**，并明确区分"文献说的"和"我的推断"。前沿本来就是证据不足的地方，推断不可避免——但必须标出来。

**文献首次出现时给题名**：「作者（年份）《题名》」，之后再提才简写成「作者（年份）」，预印本首次出现时标明。简报正文没有紧挨着的参考文献表，光写作者年份读者对不上是哪篇。附录里那张文献清单（题名 + DOI）**不能省**——一份说"你错过了这些"的简报，读者拿不到那些论文就等于没写。

**控制在 1500–2500 字。** 前沿的价值在时效和判断，不在完备；写长了没人读，而且会不可避免地滑向综述。

**模板里两种引用块，别搞混。** 以 `〔写作指导〕` 开头的那些是写给你看的，**整块（到空行为止）都不进简报**，一条都不许留；其余 `>` 引用块——目前只有开头那条覆盖行——**是简报的一部分**，原样保留并把占位符填好。

**章节名和标签用学术措辞，不用口语。** `〔写作指导〕` 块里可以随便说话；但**凡是会出现在简报里的标题、表头、字段名，都按学术文体写**。「主要研究团队及其研究脉络」不是「值得盯的团队」，「未决争议」不是「还在争什么」，「既有结论的修正」不是「需要修正的认知」。这份东西会被转发给导师和同事看。

写完在对话里给三句话摘要：最重要的一条发现、最该盯的一个人或团队、简报路径。

## 诚实边界

- **搜不到 ≠ 没发生。** 写清在哪些源、用哪些词、什么时间窗内没找到。
- **预印本要标明是预印本。** 未经同行评议这件事读者有权知道，而前沿简报里预印本占比会很高。
- **一个 id 都不许编。** 每个 DOI / arXiv id 都必须 `fastpaper get` 回源确认过。
- **只用纯 Markdown，不写 HTML 标签。** KyDog 的渲染器没有 rehype-raw，`<details>` 之类会原样显示。
